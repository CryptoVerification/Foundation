# 意味論に依存しない論理への再構成

目標は、意味論に依存しない理論提示と導出を作り、現在の暗号論理をその具体例として再構成することです。既存の帰着コード、停止証明、資源値、分布の実現、優位性上界を保持します。

現在は一般の理論翻訳とそのメタ定理に加え、暗号化と認証の異なる二つの仮定を使う規則について、意味論の合成定理と具体的な有限コード・資源の証拠への接続が完了しています。以下の振り返りは作業順の記録です。各時点の「残る作業」の現在の状況は、末尾の完了監査にまとめています。

## チェックポイントと完了条件

1. 構文とモデルを分離します。任意の有限個の前提を持つ規則、有限の仮定文脈、導出、置換、置換の恒等則と結合則を定義します。証明の構造を保持するモデルに対して解釈とその一意性を証明します。
2. 実装を振り返ります。構文に暗号の意味論が入っていないか、規則の型付けと等式の扱いが明確か、未証明の一般化を主張していないかを確認します。必要な修正を行います。
3. 暗号の理論提示を構成します。公開インスタンスの族を表すパラメータとその変換を安全性から分離し、現在の単一帰着と二前提帰着を一般規則の具体例にします。既存の導出全体との対応を証明します。
4. コード抽出を接続します。新しい導出から意味論を評価せずに計画を生成し、旧導出の計画との一致を証明します。既存の停止・資源・分布・優位性の保証を接続します。
5. 実装を再度振り返ります。複数の解釈、同じ仮定の複数使用、仮定の置換、実際の共通鍵暗号の導出を検査します。全体ビルド、公理依存、未証明部分を確認します。

## 範囲

最初の核は、判断の集合と有限個の前提を持つ規則を提示する証明項計算です。任意の依存型の一般化代数理論や、無限個の引数を持つ演算を実装したとは主張しません。規則の前提数はゼロも許します。閉じた証明の成立は解釈側に必要であり、意味論上の任意の主張を無条件で証明する規則にはしません。

既存の暗号論理は公開インスタンスの族を Lean の関数として受け取ります。新しい核もパラメータの有限符号化を無条件には要求しません。実行コードとコード生成を有限の構文に制限する既存の保証は保持します。

### チェックポイント1・2：構文の核と最初の振り返り

`Foundation/Logic/Presentation.lean` は暗号のモジュールをインポートしません。判断の集合、規則ごとの前提数、前提と結論を与えるだけで導出を作ります。置換の恒等則・結合則、解釈と置換の整合性、解釈の一意性、空の文脈に対する初期性を証明しました。モデルの値は命題に限定せず、証明や数値も保持できます。

検査用の例では、ゼロ前提の規則と三前提の規則を使いました。同じ仮定を三回使った証明の数値解釈と、仮定を閉じた証明で置換した結果を実行しました。異なる判断の仮定をそのまま結論に使う項は型検査で拒否されます。

振り返りでは、次の点を確認しました。

- 初期性は、提示した規則の自由な証明項モデルに対するものです。任意の意味論上の真理が証明可能だという完全性ではありません。
- 規則の前提数は一般化しましたが、任意の依存型の一般化代数理論を実装したわけではありません。
- 任意の証明を意味論上の結論だけで同一視しません。現在必要な置換の法則は、証明項そのものの等式として証明します。追加の証明等式を採用する場合には、コードと資源を含む各解釈が保存することを別途要求する必要があります。
- 暗号への接続では、仮定の公開インスタンスの族と安全性を混同しないように、パラメータの型・変換とその解釈の証拠を分けました。旧 API に接続する場合だけ、パラメータを従来のインスタンスの族に具体化します。別に、変換を構文として保持する記号的なパラメータも用意します。

振り返りでは、旧 API への接続が計算できない意味論を実行コードに持ち込む不備を発見しました。最初の接続は解釈後の証明構造からコンパイラ計画を作っており、既存のコード生成の実行例が失敗しました。接続を修正し、実行に使う計画とコンパイラを構文から直接生成し、解釈後の証明構造を正しさの証拠にだけ使う形にしました。また、擬似乱数生成器からの暗号の導出を、意味論上の公開メッセージの族を保持する導出から、パラメータが `Unit` の固定した導出に変更しました。公開メッセージの族は後から解釈します。既存のコード生成・43遷移での実行・42遷移での未完了の例が通ることを確認しました。

厳密な旧 API との往復には従来のインスタンスの族をパラメータとして具体化します。これは全ての意味論上の族を有限の式に符号化したという主張ではありません。意味論を受け取らない導出の例には固定したパラメータと、変換を構文として保持する `FamilyExpr` の両方を用意しました。

## 再構成後の論理の監査

再構成後に、既存の証明を読み直し、論理の公開インターフェースから独立した検査用の定理を `Foundation/Examples/LogicAudit.lean` に追加しました。新しい推論規則は追加していません。検査結果は、今回の有限前提の論理と、証明付きの暗号解釈への接続に論理的な不備を認めない、というものです。

- `refuting_model` は、仮定が成立し結論が成立しないモデルがある場合、その結論の導出が存在しないことを証明します。追加の公理に依存しません。
- `no_closed_without_nullary` は、全ての規則が少なくとも一つの前提を必要とするなら、空の仮定からの導出が存在しないことを証明します。循環する規則にも適用できます。追加の公理に依存しません。
- `provable_iff_all_models` は、導出の存在と、規則を満たす全ての命題を値とするモデルでの成立が一致することを証明します。逆方向では導出の存在自体を値とするモデルを作り、`Classical.choice` を使います。特定の暗号の意味論で真なら必ず証明できる、という主張ではありません。
- `no_unconditional_derivation` は現在の暗号の具体例に上の結果を適用します。単一前提・二前提の規則だけで、仮定なしの安全性を生成することはできません。

暗号への接続も確認しました。帰着の向きは、変換先の安全性から元の安全性を導く向きです。パラメータの解釈には、帰着が使う公開インスタンスの変換との一致が要求されます。意味論の登録には、構文に登録したコンパイラとの一致が要求されます。優位性の上界は登録済み帰着の証明から得られます。資源・停止・分布の証明書は生成したコードに対応する証拠を保持します。

この監査後の `lake build Foundation` は成功しました。新しい四つの検査定理と既存の接続を含む15宣言の公理依存を再確認し、未証明の穴や独自の公理への依存はありませんでした。追加した検査は `Foundation.lean` に接続し、今後の全体ビルドにも含めます。

正しさの範囲は、提示した規則が解釈で保存されるという条件の下での健全性です。任意の理論提示が無矛盾であるという主張ではありません。前提なしで偽を結論する規則を外から指定すれば、その偽が成立しない命題モデルを与えることはできません。また、実行時間の単位や攻撃者の範囲は各実行機械の定義に依存します。一般の論理が実行時間の意味を独自に保証したという主張にもなりません。

## 理論翻訳への拡張：チェックポイント

次の目標は、理論の規則を別の理論の導出へ翻訳し、恒等・合成・置換との整合性・解釈との整合性を証明することです。具体例では二つの帰着の合成を一つの規則として提供し、既存の導出へ展開した際のコードと上界を保存します。さらに暗号化してから認証する方式の合成定理へ接続し、意味論から有限コードと実行資源への接続を進めます。

### 翻訳の核と最初の振り返り

`Foundation/Logic/Translation.lean` は暗号のモジュールを参照しません。判断の写像と、各規則を対応する前提から結論への導出に対応させる写像を定義します。前提の数や使用回数を一律には制約せず、対象の規則が必要とする全ての前提を型で指定します。恒等翻訳、翻訳の合成、両側の恒等則、合成の結合則、導出の翻訳と置換の整合性を証明しました。

翻訳先のモデルから翻訳元のモデルを構成する `pullback` と、翻訳と解釈の順序を交換できる `eval_translate` を証明しました。任意の二つのモデルの解釈が自動的に一致するという主張はしません。`eval_preserving` では、保存したいモデルの演算を保つ写像を追加の証拠として要求します。

振り返りでは、翻訳が判断を同一視できるため、導出の保存から逆方向の導出可能性を無条件には主張できないことを確認しました。また、規則の導出への展開は前提を複数回使用したり使用しなかったりできます。従って、コード・上界・実行資源の保存は論理の翻訳だけで仮定せず、別のモデルの保存条件として扱います。

### 二つの帰着を一つの規則にする具体例

`Crypto/Logic/Presented/CompositeRule.lean` は既存の単一前提・二前提の規則を保持し、二段階の帰着を一つの規則にした理論を提供します。その規則を二つの輸送へ翻訳します。コードは一つの合成コンパイラとして解釈します。優位性の上界は二つの損失関数の合成として独立に指定します。`codePreservation` と `lossPreservation` が保存条件を満たすことを示し、任意の導出・入力コード・前提の優位性の関数について一致を証明しました。資源のモデルには、展開した明示的な証明構造を保持するモデルを指定します。実行機械ごとの時間の単位を一般の理論が勝手に作ることはありません。

`Examples/TheoryTranslation.lean` の具体例では、最初に停止命令を追加し、次に全体を定数を返すコードに置き換えます。順序を逆にすると命令列が異なることを証明しました。コード生成の実行結果は元の仮定の位置1を保持します。生成した定数コードには実際の一遷移の停止予算を持つ証明書が付くことも確認しました。

### 暗号化してから認証する方式：意味論の段階

`Constructions/Symmetric/EncryptThenMAC` で、状態を持つ暗号化とメッセージ認証の構成を定義しました。暗号化の失敗を明示的な `none` とし、失敗は認証しません。認証対象は暗号文の型に含まれる全データです。暗号化鍵と認証鍵は別々の確率計算で独立に選びます。復号では認証を確認してから暗号文を復号します。

意味論の合成の題材は [Bellare と Namprempre の認証付き暗号の合成の研究](https://eprint.iacr.org/2000/025) に対応する構成方法です。この実装で証明する具体的な安全性の範囲は次の定義です。

- 秘匿性は、適応的な暗号化問い合わせを行う選択平文の左右識別ゲームです。復号オラクルはまだ含めません。
- 完全性は、適応的な暗号化問い合わせの後に、以前に返されなかった有効な暗号文・タグの組を出力する確率です。
- 認証の仮定は、以前に署名した暗号文でも新しい有効なタグとの組が偽造になる、強い偽造困難性です。
- 合成した安全性の優位性は、上記の秘匿性の優位性と偽造確率の最大値です。

`privacy_simulation` は、認証鍵を自分で選ぶ暗号化への帰着と元の秘匿性ゲームの結果分布の一致を証明します。`integrity_simulation` は、暗号化鍵を自分で選ぶ認証への帰着について、最終候補と署名済みの組の全記録が一致することを証明します。`privacy_queries` と `integrity_queries` は問い合わせ上界を保存します。完全性の帰着では暗号化失敗の分だけ署名問い合わせが減ります。これらは問い合わせの上界であり、ホスト言語の関数を CPU の一遷移と数えた上界ではありません。

`Security.lean` は二つの異なる仮定からの数値的な上界を証明します。`Logic.lean` は、その合成を一つの高水準の規則として構文だけで定義します。高水準の固定した導出を、秘匿性・完全性・上界の合成の三つの下位規則へ翻訳し、モデルで解釈して合成定理を得ます。

この段階で方式専用の有限 CPU コードと実行時間の証明は未接続です。`sourceClass` は二つの帰着先での許容条件を要求します。実際の実行機械への接続では、元の停止・資源・分布の証拠からこの条件を証明する必要があります。一般の理論翻訳と、二段階帰着のコード・上界を保存する直近の具体例は実装しましたが、暗号の合成方式への実行機械の接続を含む全体の目標は継続中です。

### 実行機械への接続の条件

`EncryptThenMAC/Operational.lean` は、意味論上の三つの安全性の目標に対応する実行機械と、二つの有限コンパイラを受け取る接続を追加しました。`Realization` には各コンパイラが生成するコードそのものについて、帰着先の攻撃者を実現する証明と、元の資源の型を持つ停止・実行証拠を要求します。この証拠から一般の実行機械の論理に登録できる二前提帰着を構成します。元の攻撃者の実行証拠から、意味論の `sourceClass` が要求する帰着先の許容条件も導きます。

### 二つの帰着の統合と今回の目標の完了監査

`Foundation/Constructions/Symmetric/EncryptThenMAC/ConcreteOperational.lean` は、秘密性と認証の帰着を同じ有限コード体系に登録します。元のコードは二種類の攻撃者の有限命令列の組です。これは安全性の目標 `goal` が秘密性攻撃と認証攻撃の組を受け取ることに対応します。暗号化側のコンパイラは一つ目の命令列、認証側のコンパイラは二つ目の命令列を、それぞれ既に証明した固定の帰着機械の構文へ対応させます。解析予算や入力は実行証拠の資源にあり、コードへ証明や意味論の決定木を埋め込んでいません。

`encryptionWitness` と `macWitness` は、元の実行証拠から帰着先の実行証拠を構成します。これらは実際の停止証明、型付きの安全性ゲームとの分布の一致、および対象の攻撃者のクラスへの所属を持ちます。`realization` は、これまで要求だけを定義していた `Operational.Realization` の具体的な値です。`certificate` は、この値から二つの異なる仮定を使う認証済みの帰着を構成します。

`translated_codes` は、高い水準の合成規則を三つの小さい規則へ展開した後、純粋な実行計画が出力するコードを証明します。`translated_witnesses` は、そのコード一覧が、実際の実行証拠から生成した証拠一覧のコードと一致することを証明します。既存の一般定理 `witnesses_preserved` は、任意の高い水準の導出と前提の継続について、資源を含む証拠全体の保存を保証します。`encryption_resources` と `mac_resources` は、元の二つの資源情報をそれぞれ厳密に保持します。

タグのビット数を `w`、秘密性攻撃の元の段階数の上界を `T_E`、認証攻撃の元の段階数の上界を `T_M` とすると、`execution_bounds` は次の二つの帰着機械の段階数の式を保証します。

- 暗号化側は `12*w + 5 + T_E*(29*w + 39)` 段階以内です。
- 認証側は `3 + T_M*(5*w + 36)` 段階以内です。

これらは外部オラクルの内部計算と区別した帰着機械の段階数です。`bounded` は、登録した暗号化攻撃のクラスに対する上界 `ε` と、登録した認証符号の攻撃のクラスに対する上界 `δ` から、実際の元の攻撃者のクラスについて `ε+δ` を導きます。`secure` は、帰着先二つの安全性仮定から、同じ元のクラスについて無視できる成功度を導きます。

`Examples/EncryptThenMACConcreteOperational.lean` は、二種類の停止する攻撃者から、統合した実行証拠を構成します。二種類の攻撃に別々の入力を設定し、各入力が対応する資源に残ることを確認します。タグ幅2ビット、元の上界がそれぞれ1段階の例では、帰着の上界は暗号化側126段階、認証側49段階です。別に、異なる長さの命令列を純粋な計画へ入力し、異なる仮定の番号とコードが所期の順序で出力されることを実行検査します。

今回のユーザー目標に対する確認は、次のとおりです。各一般定理の型は任意の導出を量化しており、固定例の成功だけを根拠にはしていません。

| 元の要件 | 現在の証拠 |
|---|---|

| 恒等翻訳と合成 | `identity`、`comp`、`translate_identity`、`translate_comp`、左右の恒等則と `comp_assoc` を型検査しました。 |

| コードと資源について保存する内容を明示 | コード・損失・完全な実行証拠のモデルと、その保存を満たす写像を別に定義しています。`Operational.code_preserved`、`loss_preserved`、`witnesses_preserved` が任意の導出について成立します。 |

一般の翻訳とメタ定理、二段の帰着の規則化、異なる二つの仮定による暗号の意味論上の合成、具体的な有限コードと資源への接続という今回の目標は達成しました。具体的な実行への接続は、一回限りの1ビット暗号化と二行の認証表を対象とします。任意の暗号方式の実装を自動的に得る定理でも、認証表そのものの偽造困難性を無条件に証明する定理でもありません。安全性の目標は選択平文攻撃に対する秘密性と暗号文の偽造困難性であり、選択暗号文攻撃に対する秘密性の定理は別の課題です。
