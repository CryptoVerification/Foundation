# 厳密一様 sampling と期待停止時間

対象 issue: https://github.com/CryptoVerification/Foundation/issues/2

## 決定した方針

ユーザーの「厳密性維持」の指定に従い、数学的な厳密一様分布を維持します。素数位数の scalar sampling は rejection sampling とし、期待停止時間を扱う別の実行意味論を追加します。既存の全分岐 `Machine.PolynomialTime` は維持します。通常の rejection sampling に `HaltsWithin` を与えません。

厳密 sampler を構成する作業と、有限予算で厳密 sampling が不可能であることの証明を分けます。後者の基礎定理は `Foundation/Machine/FiniteRandomness.lean` に実装しました。期待操作回数と有限期待時間からの非停止確率の収束は `Foundation/Machine/ExpectedExecution.lean` に実装しました。停止出力の極限分布は `Foundation/Machine/LimitExecution.lean` に実装しました。変更はローカルにあり、未コミット・未公開です。一般の正の法を入力する一つの有限 rejection sampler と、その厳密一様性・全入力の期待時間上界を実装しました。群演算の要求形式への接続は Issue #3 で扱います。

## 有限予算の制約

既存の公平な `randomBit` と `evalConfigWithin` に対し、B rounds の確率分布は B 個の公平ビットからの像として表せます。決定的な命令と停止後の検査では対応するビットを無視します。これは証明用の coupling であり、未使用ビットを実機の操作として加算しません。

実装した theorem は次のとおりです。

- `evalConfigWithin_eq_uniform_bits`：既存 evaluator と有限 random tape の像の一致。
- `evalWithin_event_dyadic`：任意の事象確率が `count / 2^B`。
- `card_dvd_pow_two_of_exact_uniform`：任意の decoder を通して厳密一様なら `card α ∣ 2^B`。
- `no_exact_uniform_of_odd_prime_card`：奇素数個の値に対する厳密一様分布とは一致しません。

この制約は decoder を任意の Lean 関数にしても変わりません。数学的な uniform PMF を単位コスト命令として新設しません。

## 期待時間の意味論

`Foundation/Machine/ExpectedExecution.lean` では、既存の stepPMF と有限 evaluator を使います。以下の基礎定義・定理を実装しました。

- `timeoutProbability`：有限 evaluator が timeout を返す確率。
- `expectedSteps`：以下の tail sum。
- `expectedSteps_le_of_haltsWithin`：全分岐の停止上界から期待操作回数の上界を導きます。
- `AlmostSureHalts`：非停止確率が時刻を増やすと0に収束するという定義です。無限乱択列の標本空間はまだ構成していません。
- `almostSureHalts_of_expectedSteps_ne_top`：有限期待時間からこの収束を証明します。
- `PolynomialTime.expectedPolynomialTime`：既存の最悪時間の property から期待時間の property を導きます。
- `ExpectedPolynomialTime.almostSureHalts`：全入力についてこの収束を導きます。
- `HaltsWithin.almostSureHalts`：全分岐の有限停止上界からこの収束を直接得られます。

固定 input に対して `alive t` は t 操作後に Configuration が停止していない確率です。期待操作回数は ENNReal の tail sum

```text
expectedSteps p input = Σ' t : Nat, Pr[alive after t steps]
```

とします。t=0 を含めるので、一回の halt 命令は一操作です。停止後の吸収は追加の操作として数えません。

`LimitExecution.lean` は停止出力 bits の質量 `outputMass` を `sup B, evalWithin p input B (some bits)` と定義します。各質量の単調性と総質量が高々1であることを証明しました。非停止確率が0に収束する場合に総質量が1であることを証明し、初めて確率質量関数（PMF）`evalLimit` を構成します。停止しない code を無条件に正規化しません。返す質量は期待時間の上界 witness に依存しません。

- `evalWithin_some_monotone`：各停止出力の有限時間の質量の単調性。
- `outputMass_tsum_le_one`：停止しない code も含めた総質量の上界。
- `outputMass_tsum_eq_one`：`AlmostSureHalts` のもとで総質量が1になること。
- `evalLimit_map_some_of_haltsWithin`：全分岐の有限停止上界がある場合の既存 evaluator との厳密な一致。

`Foundation/Examples/LimitExecution.lean` は即時停止と公平ビット出力の一致を確認します。無限に jump する有限コードについて、停止出力の総質量が0、期待操作回数が∞、`AlmostSureHalts` が成立しないことも証明します。無限乱択列の測度空間は構成していません。極限分布は既存の有限 evaluator から定義したものです。

Program property は次の形にします。

```text
ExpectedPolynomialTime p :=
  ∃ q : Nat → Nat,
    PolynomiallyBounded q ∧
    ∀ input, expectedSteps p input ≤ (q input.length : ENNReal)
```

これは全入力で有限期待時間と almost-sure termination を要求します。全乱択 branch の有限停止とは区別します。既存 PolynomialTime からこの property への一方向の theorem を証明します。期待時間から最悪時間への逆向きは証明しません。

## 実際の exact sampler

scalar domain は正の q に対する `Fin q` です。機械への入力は、末尾が1である canonical little-endian binary `q.bits` です。候補幅 `k` はその入力ビット長です。以前の仕様では最小の候補幅を選んでいましたが、実装では法の各ビットに対して一つの候補ビットを生成する方式に変更しました。2の冪では候補が一ビット長くなります。成功確率は依然として少なくとも1/2で、厳密一様性は変わりません。

1. k 回の公平な randomBit を読み、固定幅の binary z を作ります。
2. `z < q` なら Fin q の canonical encoding を出力します。
3. それ以外は両テープのヘッドを実命令で戻し、前の候補を上書きして再試行します。
4. q=1 は z=0 を返す専用の有限経路です。q=0・壊れた入力は有限時間で拒否します。

候補生成・比較・出力整形は実際の一セル命令で実装しました。サンプラー単体は正準な法のビット列を受け取ります。安全性 parameter と instance code の外部 frame の解釈と固定幅 scalar code への接続は Issue #3 の暗号アルゴリズム側で扱います。既存の要求形式は変更していません。

各試行の成功確率は `q/2^k` で、少なくとも1/2です。各値の一試行での出現確率が同じであることと幾何級数を使い、最終出力が厳密 uniform Fin q であることを証明します。期待試行回数は高々2です。検査・両ヘッドの復元を含む一試行の上界は `10*k+7` 操作です。入力検査も加算し、全ての raw input について `24*(input.length+1)` 操作の期待上界を証明しました。無限に reject する分岐を削除していません。timeout の確率が0に収束することを証明しました。q=3では有限の全分岐停止上界が存在せず、この一般コードは既存の `PolynomialTime` を満たさないことも証明しました。

### 証明の所在

- `Foundation/Machine/RejectionSampling.lean`：一つの固定コード、空・不正入力の停止、入力検査・候補生成・比較・拒否後のヘッド復元の遷移証明。
- `Foundation/Machine/RejectionSamplingSemantics.lean`：`eval_trials`、`trialWeights_none`、`trialWeights_some`、`expectedSteps_le`、`expectedPolynomialTime`、`evalLimit_nat`、`evalLimit_nat_decoded`、`not_polynomialTime`。有限 evaluator から幾何級数を経て厳密一様な極限 PMF を得ます。
- `Foundation/Machine/RetryExpectation.lean`：検査前処理の操作数と幾何級数の tail sum を合計する小さな補題。
- `Foundation/Examples/RejectionSampling.lean`：一般の q の定理と q=1,3,4 の境界、全入力の期待時間を確認します。q=3だけの旧作業用コードは、一般コードが同じ性質を証明できたので除去しました。

## ElGamal の安全性との接続

コードを確認すると、`RepresentedChooseNormalizer.simulatorCode` は source、normalizer、multiply のコードだけを合成します。scalar sampler と powerProgram は呼び出しません。

Issue #3 の `RepresentedSimulatorPrimitives` により、シミュレータに必要な証明を独立させました。最終 native security theorem は sampler の全分岐停止証明を要求しません。sampler が期待時間でも、シミュレータと攻撃者の既存 machine-PPT class は最悪時間のまま維持できます。新しい期待時間 adversary class や、DDH hardness assumption の変更をこの issue のために導入する必要はありません。

鍵生成・暗号化自身の exact scalar sampling は期待時間で動作するアルゴリズムになります。これを厳密な最悪時間のアルゴリズムと呼びません。論文の ideal uniform games は変更しません。
