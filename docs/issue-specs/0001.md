# 旧実行モデルの削除と対応証明の撤回

対象 issue: https://github.com/CryptoVerification/Foundation/issues/1

## 決定

旧実行モデルが不要なら削除するというユーザーの指定に従い、既存コードの依存を調査して削除しました。機械モデルから旧実行モデルへの精緻化を実装する計画は撤回します。対応先を削除するため、この対応証明は完了条件から外します。対応証明や真包含を証明したという意味ではありません。

このファイルは以前の実装仕様を置き換えるローカルの決定記録です。GitHub issue 本文と状態にはまだ反映していません。

## 依存調査

全 Lean ソースの import と識別子の参照を確認しました。

- 旧実行モデルの定義は `Foundation/Resource/ExecutionSemantics.lean`、`ExecutionCost.lean`、`PolynomialExecution.lean` の3ファイルにありました。
- 利用箇所は旧モデル専用の例5ファイルと、`Foundation/Constructions/ElGamal/ConcreteSecurity.lean` の旧 `secureINDCPA_of_secureDDH`、その確認例でした。
- `MachineSecurity.lean` の `secureRepresentedINDCPA_of_secureRepresentedDDH_nativeMachinePPT` は、機械コードの意味・停止・class 保存から既存 `Reduction.secureOnWithin` を直接使います。旧実行モデルの定理は使いません。
- `MachineAdversaryInterface.uniformModel` と抽象 uniform class への変換定理は、互換性の確認例と到達可能 request に関する同種の変換定理だけで使われていました。機械モデルの安全性輸送は使いません。

## 削除範囲

定義3ファイルと専用例5ファイルを削除しました。

```text
Foundation/Resource/ExecutionSemantics.lean
Foundation/Resource/ExecutionCost.lean
Foundation/Resource/PolynomialExecution.lean
Foundation/Examples/ExecutionSemantics.lean
Foundation/Examples/ExecutionCost.lean
Foundation/Examples/PolynomialExecution.lean
Foundation/Examples/PolynomialExecutionReduction.lean
Foundation/Examples/PolynomialExecutionComposition.lean
```

旧 ElGamal 定理と確認例、ルートの import を削除しました。機械側では `uniformModel`、その有限記述 witness、`pptClass_admissible_uniform`、`indCPAReindexedReachablePPTClass_admissible_uniform` と対応する例を削除しました。

抽象 uniformity と program resource の共通 API は、既存の program/resource bound と合成例に独立した利用があるため残します。`UniformAdversaryModel`、`ProgramResourceMeasure`、`ProgramTransformation` とそれらの resource bound は、削除した実行モデルの定義に依存しません。

## 機械モデルで維持する結論

機械側の `pptClass`、実遷移、有限符号化、全入力・全分岐停止、到達可能 request の上界、program transformation の合成、ElGamal の機械モデル上の安全性輸送を維持します。厳密 sampling の一般コードと期待時間は Issue #2 の仕様に沿って証明済みです。具体的な群演算と暗号アルゴリズムの接続の未完了箇所は Issue #3 に残ります。
