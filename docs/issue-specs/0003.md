# 素数位数の群表現と ElGamal の機械実装

対象 issue: https://github.com/CryptoVerification/Foundation/issues/3

## 現在の状態

固定有限乗算コードと、任意の choose 応答を検査する有限正規化コードを構成しました。`PrimeOrderRepresentation.simulatorPrimitives` と `PrimeOrderRepresentation.chooseNormalizer` の全 field を証明しています。`PrimeOrderMachineSecurity.secureINDCPA_of_secureDDH` は具体的な両 witness を代入しており、実装引数 `M` / `N` / `T` を要求しません。DDH 安全性は意図した暗号学的前提として残ります。**Issue #3 全体は未完了です。** 鍵生成・暗号化まで含む実装条件には、フレーム付き sampler 全体の厳密分布・期待時間証明と、鍵生成・暗号化への接続が残っています。抽選入力の準備・保存カウンター付き抽選・固定幅の返却は有限コードとして接続済みで、成功する実行分岐の証明もあります。後続の追記は履歴であり、以前に未完了と記した M / N は現在の残作業ではありません。

**scalar 抽選の有限コードと現在の証明範囲**：`FramedScalarPreparation.program` は実際の security prefix と `p,q,g` frame を読み、中央列から法を抽出します。元の固定幅のカウンターを空白セルの手前に保存し、高位ゼロを実命令で消去します。`FramedScalarInput.program` は保存カウンターを保持して法の先頭へ巻き戻します。`RejectionSampling.Saved` は既存の50命令の抽選コードについて、保護された呼出元データを保持した実行・有限回の抽選分布・拒否確率を証明します。`RejectionSampling.Saved.expectedTransitions_canonical` は、法の canonical bit 長を L として期待操作回数を `24*(L+1)` 以下に抑えます。同じファイルの `almostSureHalts_canonical` と `eventualOutputMass_uniform` は、保存データを保持した抽選処理の確率1での停止と厳密な一様分布を証明します。有限予算で停止しなかった確率を条件付き分布に正規化していません。

`ScalarSamplePadding.program` は抽選後の法を実命令で消去し、保存カウンターを読み、結果を元の固定幅へ戻します。`FramedScalarSampler.program` はフレーム処理・抽選・固定幅返却を一つの有限コードとして接続しています。`Examples/FramedScalarSampler.lean` は p=7,q=3,g=2、公開幅6ビットから候補1を抽選して固定幅コードを返す実行分岐を証明します。例の抽選分岐自体も実際の確率評価の support から構成しています。法3の抽選処理について、保存データに関係なく期待操作回数72以下と厳密な一様分布になる例もあります。

**残作業**：保存カウンター付き抽選処理単体の確率証明と、フレーム付きコード全体の確率証明は別です。後者には、乱択する副プログラムから実際の戻り命令・固定幅化の継続へ接続した全体の厳密分布と期待時間を証明する必要があります。成功する実行分岐の存在だけで、この全体証明を代用しません。さらに鍵生成・暗号化への接続が必要です。Issue #3 はこれらが残るため未完了です。

**正規化コードの現在の到達点**：`ChooseSafeValidation.program` は、security prefix・instance 幅・完全な外側応答フレームを検査してから、同じ物理テープで `ChooseValidation.program` を呼びます。本体は幅・両候補の範囲・両候補の部分群条件を順に検査します。各判定後に元の要求を実際に復旧し、失敗なら生成元の既定応答、全検査が成功した場合だけ状態を含む元の応答全体を出力します。`chooseSafeValidation_eval_normalization` は有効な instance request に対する**任意の有限応答**について既存の正規化仕様との一致を証明します。空応答・誤タグ・区切りや幅の不備・範囲外・部分群条件の失敗を含みます。

**全入力の停止と作業テープの計上**：`ChooseOuterGuard.runs_any` は不正な要求を含む全有限入力で `100*(input.length+1)+300` 手以内の停止を証明し、受理時には元の入力の実復旧と外側形式の正しさを示します。`runs_valid` は正常要求を誤拒否しないことも証明します。`ChooseCheckContinuation.runs_withCheck_bounded` は、検査が実際に作ったテープの大きさを検査の遷移数から抑え、消去と巻き戻しを含む上界を与えます。`ChooseValidationRuntime` は数値の正当性を仮定せず各段の上界を合算します。`ChooseSafeValidation.haltsWithin` と `budget_polynomiallyBounded` は**同じ固定有限コード**の全 raw 入力での多項式停止を証明します。

**出力分岐の現在の到達点**：`ChooseAcceptedOutput` はフレーム内の元の応答を任意長の状態を含めてそのまま出力します。`FramedChooseDefaultOutput` は実際の instance frame から生成元を読み、二つの同じ生成元と空状態を出力します。両プログラムについて、不正な外側フレームを含む全有限入力での多項式停止と、共通予算での evaluator 等式を証明しました。`acceptedChooseOutput_eval_normalization` と `framedDefaultChooseOutput_eval_normalization` はそれぞれの分岐を正規化仕様へ接続します。これらの出力コードは `ChooseValidation.program` の成功・失敗分岐として接続済みです。ただし、外側フレームが不正な入力も含む全入力停止と共通予算が未証明のため、`RepresentedChooseNormalizer` 全体の witness はまだ構成していません。以下の各時点の経過にある「出力未実装」は、その時点の状態です。

`PrimeOrderChooseNormalization.lean` は、受理された応答の二つの要素コードが既に正規形であり、正常時の出力は入力応答をそのままコピーできることを証明します。`validChooseResponse_iff_numeric` は受理条件を二つの delimiter、固定幅、範囲、非零、`a^q mod p = 1` の検査に正確に分解します。不正・wrong-stage 応答の既定出力も別定理で固定しました。これらは実装する機械の仕様を明確にする数学的補題であり、`N.program`、全入力の停止証明、evaluator の正しさを代用しません。

`ChooseResponsePrefix.lean`、`ChooseFirstField.lean`、`ChooseTwoFields.lean`、`ChooseResponseParser.lean` は、外側の security/instance/response frame と内側の choose tag・二つの delimiter を一つの固定有限コードで読みます。保存済みの入力 prefix と先行 parser の出力テープを引き継ぐ実遷移、全有限入力の線形停止、正規形入力での evaluator 等式を証明しました。現段階の出力は `first ++ [true] ++ second ++ [true]` という二 payload・二 status の中間表現です。固定幅、`0<a<p`、`a^q mod p=1` の機械的検査、raw state を保つ応答再構築、不正入力の generator fallback は未実装であり、`RepresentedChooseNormalizer` の witness ではありません。Nix の全体 `lake build` は 3024 jobs で成功しました。

`DelimitedWidthCheck.lean` は、delimiter 付き一フィールドと出力テープ上の幅カウンタをセルごとに比較する固定13命令を追加しました。幅が一致する場合の受理実行、長すぎる場合と短すぎる場合の拒否実行、任意の有限テープでの線形上界付き停止を証明しました。評価器の共通予算でも受理ビットが幅の等式と一致します。カウンタは全て `false` でなくてもよく、例えばコピー済みの法 `p` の固定幅コードをそのまま幅カウンタにできることも証明しました。これは二要素の幅検査を構成する部品ですが、外側の instance から法コードを適切なヘッド位置へ置き、二つのフィールドへ順に適用する接続はまだ証明していません。数値範囲・部分群条件と fallback も未完了なので、Issue #3 は引き続き開いたままです。

`DelimitedTripleWidthCheck.lean` はコピー済みの `p ++ q ++ g` 全体を、3セルで要素幅1ビットを表すカウンタとして使用します。固定15命令について、幅一致・長すぎる場合・短すぎる場合の判定と、任意の有限テープの線形停止を証明しました。`FramedInstanceResponsePrefix.lean` と `FramedInstanceResponseReady.lean` は、外側の instance/response frame を実命令で読み、instance code を出力テープに保持して先頭へ巻き戻します。`ChooseFirstWidthCheck.lean` は choose tag の拒否と最初の delimiter 付き要素の幅検査を接続し、`ChooseFirstWidthPrefix.lean` はこれらを一つの固定有限コードにまとめました。正規形 choose 応答の第一要素について `field.length = n+3` と出力 status が一致する実行・evaluator 定理、ならびに不正形式を含む全有限入力の多項式停止を証明しています。これらは `N` の前段ですが、第二要素、数値範囲・非零・部分群検査、state の保存、generator fallback を含む完全な正規化器ではありません。

続いて `ChooseSecondWidthCheck.lean` は最初の検査結果を確認し、コピー済みの instance code を実際に巻き戻して第二要素の幅を調べます。`ChooseTwoWidths.lean` と `ChooseTwoWidthsPrefix.lean` は、二つの幅検査を同じ保存された code と外側 framed request に接続しました。`PrimeOrderChooseNormalization.chooseTwoWidthsPrefix_eval` は実際の prime-order instance code で二つの幅の conjunction が status と一致することを証明します。`validChooseResponse_nativeWidths` は数学的に妥当な応答がその実コードの幅判定を通ることを証明します。どの定理も数値範囲、非零、部分群判定を主張せず、`N` の構成にはまだ届いていません。

`ChooseSecondWidthCheck.runs_second_matching_layout`、`ChooseTwoWidths.runs_matching_layout`、`ChooseTwoWidthsPrefix.runs_matching_layout` は、二要素の幅が一致したときの両テープの停止位置を保存します。入力ヘッドは任意長の state の先頭、出力ヘッドは保持した instance code の直後です。実テープの空白セルによる違いは `Tape.Equivalent` で扱います。次段の数値検査はこの保存状態から開始する必要があり、今回の位置証明は数値検査そのものではありません。

`DelimitedTapeComparison.lean` は、delimiter 付き候補を入力テープ、法の固定幅コードを出力テープから一セルずつ読み、候補の値が法より小さいかを判定する固定有限コードです。比較後の二本のテープ配置、同じ数値比較との一致、不正・途中切れを含む全有限テープでの線形停止を証明しました。結果は入力側の delimiter に書き、保存済みの `p ++ q ++ g` を壊しません。`ChooseSecondFieldRewind.lean` は幅検査後の停止位置から第二要素と instance code の先頭へヘッドを戻す実命令・全入力停止・有効配置での `Tape.Equivalent` を証明します。`ChooseRangePreparation.lean` と `ChooseSecondRangeCheck.lean` はこれらを二幅検査の prefix と一つの固定プログラムに接続し、全有限入力の多項式停止と、有効な二要素応答における第二要素の `value < modulus` 判定の実行トレースを証明しました。`ChooseFirstFieldRewind.lean` は比較後の実テープから第一要素と法の先頭へ戻し、`ChooseFirstRangePreparation.lean` と `ChooseTwoRanges.lean` は第一要素の比較まで一つの固定有限コードに接続しました。`ChooseTwoRanges.runs_both_ranges_decisions` は両 delimiter の判定ビットが二要素それぞれの数値範囲と一致することを示します。`ChooseTwoRanges.eval_both_ranges_layout` は公開された多項式予算での評価器にも同じ物理配置を与えます。`PrimeOrderChooseNormalization.chooseTwoRanges_decisions` はこれを具体的な素数位数 instance code に適用し、`validChooseResponse_nativeRanges` は数学的に妥当な応答が両比較を通ることを示します。全有限入力の多項式停止も証明済みです。**これらの範囲検査を受理条件としてゲートする制御、両要素の部分群検査、成功時の応答再構築、不正時の generator fallback は未接続で、`N` は未構成です。**

非零判定だけの独立した20命令コードも検証しましたが、`validChooseResponse_iff_numeric_without_nonzero` を証明したため削除しました。scalar order が正なら、`a^q mod p = 1` は `a ≠ 0` を含意します。正規化器では数値範囲と部分群所属を同じ実テープ上で判定する必要があります。独立した非零走査とその再接続は不要です。

## 仕様の結論

数学的な ElGamal の ideal uniform games と、攻撃者・シミュレータの既存 machine-PPT class を維持します。Issue #2 に従い、scalar sampling だけは厳密一様な期待時間アルゴリズムとして証明します。

`RepresentedSimulatorPrimitives` を実装し、native simulator が使う乗算と符号化だけを最終安全性定理の前提にしました。sampler と累乗の停止証明は要求しません。従来の全演算 interface `RepresentedMachinePrimitives` は保持し、必要な field を取り出す `toSimulatorPrimitives` を追加しました。素数位数の群表現・数学的 codec・membership・復号の正しさを実装しました。比較・加減算・二倍剰余・剰余加算の有限ビットコードについて、正しさと全入力の線形停止上界を証明しました。剰余乗算用の作業領域の初期化、未処理ビットの選択、算術入力の準備、累積値の書き戻しも実装しました。乗算の部品を一つの有限コードとして接続し、全入力の停止上界と妥当な入力での剰余積の正しさを証明しました。完全な累乗コードと作業幅を広げた乗算コードは実装済みです。高位の作業ビットを消して外部幅の結果を返す有限コードも接続済みです。生の三数入力について、乗算・累乗の出力が具体的な素数位数群の `elementCode` による積・累乗の符号化と一致する定理も証明しました。累乗の作業幅拡張と高位ビット消去も実命令で接続しました。`FramedArithmeticPrefix` は unary security parameter と instance frame を一つの有限コードで消費し、妥当な入力で最初の element frame に到達することと、任意の有限入力の線形時間停止を証明しました。element frame の値を取り出して生の三数入力へ並べ替える処理、および choose normalizer の有限コードは未完了です。変更はローカルにあり、未コミット・未公開です。

## 群と parameter domain

採用する表現は、素数 p に対する有限体の乗法群の、素数位数 q の巡回部分群です。公開 parameter は `p,q,g` です。数学的な domain は p と q の素数性、g の位数が q であることを要求します。safe-prime `p=2q+1` や、そのような無限族の存在は要求しません。

`X n` は `p < 2^(n+3)` を満たすこれらの parameter です。proof field はコードに入れません。群は `Subgroup.zpowers g`、scalar は `Fin q` とします。generator power の全単射、`FiniteAlgebra.power_mul`、群乗算、逆元・共有鍵の交換則を証明します。

家族 F は X の有効な parameter を選びます。family を与えることと、その DDH hardness は別です。安全な parameter の自動生成、素数生成、parameter 検証の多項式時間性は今回の結論に含めません。

## codec の仕様

- endian は little endian に統一します。幅は `w=n+3` bits です。
- instance code は p,q,g の固定幅3フィールドです。長さは3wです。
- element と scalar の code はそれぞれ固定幅wです。
- scalar decoder は幅不一致または値がq以上なら拒否します。
- element decoder は幅不一致、0、p以上、または `a^q mod p ≠ 1` なら拒否します。これが `Subgroup.zpowers g` の membership と一致することを、有限体の乗法群の巡回性と g の位数から証明します。
- 上記を既存の `Machine.frame` と request/response codec に組み込みます。`n` の unary encoding は維持します。

instance の mathematical decoder は domain の validity を確認します。その Lean 関数を効率的な機械操作とは扱いません。native operation は、正しい parameter 入力について意味の一致を証明します。すべての raw input では、有限 parser と bit-level 算術によって停止を証明します。raw parameter が prime であるかの判定を無証明の無料命令にしません。

### Issue #3 を閉じるための証明義務

最終安全性特殊化の M / N はいずれも構成済みです。残る issue の実装条件は、下記の sampler の要求処理・固定幅出力、および鍵生成・暗号化への接続です。

## 群の実コード

`BinaryComparison.lean`、`BinaryAddition.lean`、`BinarySubtraction.lean` に比較・加減算の有限一セルコードを実装しました。全入力の上界は比較が `5*(L+1)`、加減算が `7*(L+1)` 操作です。不正な奇数長入力も停止します。各コードの数値的正しさを実際の evaluator から証明しました。`BinaryDoubleReduction.lean` は `2*x+b` の条件付き減算を一つの有限コードで実装します。`x<p` と作業幅に倍値が収まる条件のもとで、正確な剰余と固定幅 output を証明しました。復元・再書き込みを含めた全入力停止上界は `18*(L+1)` 操作です。`BinaryModularAddition.lean` は剰余加算を409命令の有限コードで実装し、両オペランドが法より小さく、和が作業幅に収まる場合の正しさを証明します。全入力停止上界は `24*(L+1)` 操作です。`BinaryArithmetic.lean` では p=7 で減算する経路と元の候補を戻す経路を確認します。剰余乗算全体の有限コード・全入力停止・数値的正しさは証明済みです。累乗の有限コードと停止・数値的正しさは証明済みです。サンプラーの要求形式処理と鍵生成・暗号化への接続は残っています。乗算・正規化の要求処理は証明済みです。長い剰余・shift-and-add 乗算・square-and-multiply を使います。Nat の値に比例する反復を binary 入力の多項式時間と誤認しません。

- 乗算は p を法とする積を返します。
- 累乗は scalar の bit 数だけ反復し、square-and-multiply のループ不変量から正しさを証明します。
- malformed fields と p=0 などは有限の拒否経路を持ちます。
- 長さ全体に対する明示的な `C*(L+1)^d` budget を実命令から導きます。最小の次数は要求しません。
- Issue #2 の expected exact sampler を別 witness として構成します。
- choose normalizer は response tag、delimiters、固定幅群要素の validity を検査します。正常応答では raw state を保持し、不正・wrong-stage 応答では generator を両メッセージとし state=[] の既存 fallback を出力します。

`Group` の数学的な乗算・累乗・decoder を、そのまま機械命令として呼びません。

## 検証と残る仮定

固定された小さな regression instance として p=7,q=3,g=2 を使います。これは一般の prime-order subgroup 実装を検証する例であり、暗号学的に安全だとは主張しません。二要素の toy group だけで論文対応を完了したとは報告しません。

最終 theorem では、有効 parameter family F に対する DDH machine-PPT hardness を残します。具体 codec・乗算・normalizer の M/N field は構成済みの定義で discharge します。expected keygen/encrypt の実装は、native worst-case simulator の証明と別に報告します。

`Foundation/Machine/CompleteFrameCheck.lean` に18命令の固定コードを追加しました。unary 長さヘッダーを読むたびに実カウンターを書き、本文の各ビットを確認してからカウンターを消します。ヘッダーの区切りがない場合、本文が短い場合、本文の後に余分なビットがある場合は拒否マーカーを残して停止します。ここで検査する `frame` は外側要求の長さ付きフレームであり、choose 候補に使う `FiniteBitEncoding.delimit` とは異なります。

`runs_any` は、任意の有限入力での停止上界 `11 * bits.length + 8` と、受理時の厳密な入力形を証明します。`runs_valid` はすべての正常フレームの受理を実遷移で証明します。`accepts_iff_frame` は実際の停止トレースについて、受理と一つの完全なフレームの存在の同値を示します。消費したフレームは入力テープの履歴にそのまま残り、成功時の出力カウンターは実際に消去されます。

`runs_any_loaded` は前段の実テープから同じ検査を実行します。使用するテープ同値は外側空白の違いだけを許し、要求を新しい数学的テープへ無償で置き換えません。`haltsWithin` と `polynomialTime` を追加し、`Foundation.lean` に登録しました。既存 `ChooseValidation` のコメントも、任意応答の正しさが証明済みである現在の状態に合わせました。

正規化器の外側検査全体には、security prefix と instance 幅の検査、カウンターの消去、この完全フレーム検査、元の入力への実巻き戻しを接続する必要があります。さらに、接続済みの四段検査本体の時間を一つの多項式で抑え、共通予算の evaluator 等式を得る必要があります。この部品の完成だけでは `N` は構成できず、Issue #3 は開いたままです。
