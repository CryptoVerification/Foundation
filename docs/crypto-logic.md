# 帰着プログラムを構成する小さな安全性論理

この論理は、安全性の導出から、使用した仮定と、その仮定に至る帰着プログラムを構成します。生成したプログラムには、全入力・全乱択分岐での多項式停止予算、攻撃者としての意味の保存、優位性の損失の証明が付きます。

## 意味論の対象

`BoundedProgram` は、一つの有限プログラム、停止予算 `budget : Nat → Nat`、予算の多項式上界の証明、全入力・全乱択分岐の停止証明を保持します。予算の引数は入力の総ビット長です。期待実行時間ではありません。

`SecurityObject` は、既存の `CryptoGoal`、機械の入出力を攻撃者として解釈する `MachineAdversaryInterface`、許される攻撃者の範囲 `AdversaryClass` をまとめます。各許された攻撃者が、一つの `BoundedProgram` で実現されることも要求します。インスタンスの族や安全性パラメータごとに別のコードを選ぶことは認めません。

入力長の条件は、元の攻撃者の範囲に保持します。ElGamal の対象では、ゲームが実際に到達する要求の長さを制限する既存の範囲を使用します。任意の状態を含む全要求の長さを一律に制限する条件には置き換えません。

`SecurityObject.Witness` は、特定の攻撃者について、有限コード、停止予算、意味の保存、許された範囲への所属を保持します。対象の安全性は、既存の `SecureOnWithin` と同じ意味です。各許された攻撃者の優位性が無視できるほど小さいことを要求し、全攻撃者に共通する一つの上界は要求しません。

## 認証された帰着

`CertifiedReduction X Y` は、次の情報を保持します。

- `reduction` は、インスタンスと攻撃者の変換、および優位性の損失を保持します。
- `compiler` は、既存の有限コンパイラ構文 `ProgramCompiler` です。元の有限コードだけを読みます。
- `budget` は、元の `BoundedProgram` から生成コードの停止予算を構成します。
- `polynomial` と `halts` は、その予算の多項式上界と、生成コードの全入力停止を証明します。
- `realizes` は、生成した同じコードが、意味論上の変換後の攻撃者を実現することを証明します。
- `admissibility` は、変換後の攻撃者が許された範囲に入ることを証明します。
- `negligible` は、優位性の損失が無視できるほど小さい関数を保存することを証明します。

`mapWitness` が返す証拠のコードは、必ず `compiler.run` の出力です。「別の効率的なコードが存在する」という結果だけで代用しません。

初版では、停止予算とその証明を解析用データとして扱います。予算の構成は非計算的でも構いません。ElGamal の接続では、既存の存在証明から停止予算を選びます。この選択はコード生成にも、生成されたプログラムの実行にも入りません。係数と次数を数値として計算する仕組みは、初版では要求しません。

帰着が元の入力より長い要求で攻撃者を呼ぶ場合も許します。そのため、元の予算の一つの値だけから変換後の実行時間を評価できるとは仮定しません。既存の同じ入力長に対する評価を持つ機械変換は、`ofSimulation` または `ofTransformation` で取り込めます。

## 構文と推論規則

`Language` は対象と基本帰着の名前、有限コンパイラ構文を登録します。意味論や停止予算は含めません。`Signature` はその言語の意味論を与えます。基本帰着には、認証された帰着と、言語に登録したコンパイラとの一致証明が必要です。登録簿全体が有限であることは要求しません。各帰着の式と各導出は有限の木です。

帰着の式 `ReductionExpr` には三つの構成子があります。

```text
identity X          : X から X への帰着
primitive e         : 登録した基本帰着
seq first second    : first の後に second を適用する帰着
```

安全性の主張 `Claim` は対象とインスタンスの族を持ちます。仮定の文脈 `Context` は主張の有限リストです。

導出を作る規則は二つです。

```text
hypothesis i
  文脈の位置 i にある主張を使用します。

transport r F premise
  r : X から Y への帰着と、r が F を写した族に対する Y の安全性から、
  F に対する X の安全性を導きます。
```

攻撃者の変換は X から Y へ進み、安全性の輸送は Y から X へ進みます。輸送の前提に現れる族は、必ずその帰着が写した族です。意味論上の任意の真な命題を追加する規則や、未登録の帰着を挿入する規則はありません。

実装では、実行可能な導出の構文 `DerivationSyntax` と、型が正しいことを表す証拠を分けています。`Derivation` は構文、有限コンパイラ構文、そのコンパイラが導出の構文から得られるものと一致する証明を保持します。その構文に対応する型の正しい導出木 `DerivationTree` が存在することも証明します。証明はコード生成時に消去されます。この分離により、非計算的な意味論を持つ対象についても、証拠付きの構文として構成した導出のコンパイラを実行可能な評価器で評価できます。上の二つの規則は、この証拠付きの導出を構成する関数です。`hypothesis`、`transport`、`substitute` には `macro_inline` を指定し、コード生成の開始時に関数の本体を展開します。これにより、型と証明だけに使用する意味論の引数を消去します。通常の `inline` 指定だけでは、この消去より前に非計算的な依存が残ってしまいます。`Foundation/Examples/CryptoLogic.lean` は、構造体を手で組み立てる代わりに、この三つの構成関数で導出を作り、生成コンパイラを `#eval` で実行します。

## 導出から得られる保証

`Derivation.extract` は、使用した一つの仮定の位置、その仮定に至る認証された帰着、写したインスタンスの族と仮定の族の一致証明を返します。位置は実行可能な構文から求めます。意味論の証拠は存在証明から選ぶため、この解析処理は非計算的です。

`Derivation.compiler` は、導出の構造から有限コンパイラ構文を構成します。`extract_compiler` は、この構文が取り出した認証された帰着のコンパイラと一致することを証明します。

元の停止証拠を渡すと、`runBounded` が生成コードの停止予算と証明を返します。`compiler_halts` と `compiler_polynomialTime` は、同じ生成コードの停止と多項式時間性を保証します。`mapWitness` は、実際の攻撃者の証拠を、変換後の攻撃者の証拠へ写します。`advantage_le` は、合成された優位性の損失を含む不等式を保持します。

`sound` は、文脈の全仮定が成立すると結論も成立することを証明します。`sound_of_selected` は、使用した一つの仮定の成立だけで十分であることを証明します。

`substitute` は、各仮定を別の文脈での導出に置き換えます。これにより、仮定の証明を接続できます。`extract_index_substitute` は、置換後の導出が使用する仮定の位置を正確に追跡することを証明します。`no_empty` は、空の文脈からはこの規則だけで安全性を導出できないことを証明します。これは構文についての結果であり、安全な暗号方式の不存在を意味しません。

合成の括弧付けを変えても生成コードは同じです。`seq_assoc_run` がこれを証明します。一般の証明の完全性、帰着の不存在、資源評価の最適性は主張しません。

## 導出の正規形と登録された帰着に対する完全性

`Crypto/Meta/NormalForm.lean` は、導出を一つの仮定と、その仮定への一つの帰着の式にまとめます。この形を `NormalForm` と呼びます。仮定の位置、登録された基本帰着の合成、写したインスタンスの族と仮定の族の一致証明を保持します。正規形からは、一つの安全性輸送と一つの仮定使用で構成された導出を再構成できます。

`DerivationTree.route_eval` は、まとめた帰着を解釈した証明書が、元の導出から取り出した証明書と等しいことを証明します。合成の括弧付けを変更しないため、停止予算と優位性の損失をそのまま保存します。`Derivation.normalForm_budget` と `normalForm_loss` は、公開された導出の停止予算と損失について、この保存を示します。`normalForm_index` は使用する仮定の保存、`normalForm_compiler` はコンパイラ構文の保存、`normalForm_run` は正規形から再構成した導出の生成コードの保存を示します。正規形からの再構成では末尾に恒等コンパイラを付けるため、元のコンパイラ構文との比較には実行結果の一致を使います。

`derivable_iff_registered_route` は、次の二つが同値であることを証明します。

- この論理で、指定した対象とインスタンスの族について導出を構成できること。
- 文脈のある仮定へ至る登録済み帰着の式が存在し、その式が写した族が仮定の族と一致すること。

この結果は、登録された帰着の式に対する相対的完全性です。意味論上のあらゆる帰着を表せることや、安全性が真なら必ず導出できることは主張しません。正規形の一意性、最短性、恒等帰着をすべて除去することも要求しません。この同値だけで導出可能性の判定手続きが得られるわけではありません。

`Derivation.substitute_run` は、仮定を別の導出で置き換えたコンパイラの実行が、元の導出のコンパイラと、使用した仮定の置換先のコンパイラとの順次実行に一致することを示します。これは中間の仮定を除く操作が生成コードを保存することを表します。使用しない仮定の置換先は、生成コードに寄与しません。

公開された導出から正規形を取り出す解析には、既存の型付けの存在証明から導出木を選ぶため、非計算的な選択を使います。実行用のコンパイラにはこの選択を追加しません。明示的に与えられた正規形からの導出再構成は実行可能です。`Foundation/Examples/CryptoNormalForm.lean` は、多段の輸送の統合、停止予算の保存、正規形からのコード生成の実行、および具体的な ElGamal 導出への適用を確認します。

## 二つの仮定を組み合わせる帰着

`Machine/BinaryReduction.lean` の `AdversaryTransform` は、インスタンスと攻撃者の変換を表します。`CertifiedTransform` は、その変換を実装する有限コンパイラ、生成コードの停止予算、多項式時間性、意味の保存、攻撃者の許容条件の保存を保持します。一つの枝だけで元の安全性が導けるとは要求しません。既存の一前提の帰着は `ofReduction` で取り込めます。

`CertifiedBinaryReduction X Y Z` は二つの枝と、元の攻撃者の優位性が二つの変換後の優位性の損失付きの和以下になる証明を保持します。各枝の損失は、無視できる優位性を無視できるままに保つ必要があります。`secure` は、写した族についての Y と Z の安全性から X の安全性を導きます。二つの仮定、ゲーム、乱数の独立性を要求する規則ではありません。安全性の証明は攻撃者ごとの無視できる上界を使い、全攻撃者で共通の無視できる上界を仮定しません。

`Security/ThreeGames.lean` は、この証明書を三つの確率的な実験に適用します。各実験は安全性パラメータと、真偽値の要求に確率的な真偽値を返す攻撃者を受け取ります。優位性は、二つの実験が true を返す確率の絶対差です。`probabilityGap_triangle` が端点の確率差を隣接する二つの確率差の和で抑えます。同じ有限の入出力形式を使うため、二つの枝のコンパイラは恒等変換です。隣接する二組の実験を区別できないという仮定から、端点の実験を区別できないことを証明します。外部の実験や入出力解釈自身の実行費用を、この定理で認証したとは主張しません。

`Logic/MultiDerivation.lean` は、一前提の言語と署名を保持し、登録された二枝の帰着を追加します。`MultiTree` の規則は仮定使用、一前提の安全性輸送、二前提の安全性輸送です。どの輸送でも、前提の族が帰着で写した族に正確に一致することを要求します。`MultiDerivation` は実行用のコンパイラ一覧と、型が正しい導出木の存在証明を保持します。`run` は一つの元のコードから、仮定の位置と生成コードの有限リストを返します。意味論や停止予算は実行用のコンパイラに渡しません。実行用の一覧が導出木の生成計画と一致することも証明します。

`Meta/MultiExtraction.lean` の `BranchLeaf` は、各末端の仮定の位置、元の対象からその仮定への合成された変換、族の一致証明を保持します。`extract_emitted` と `runBounded_programs` は、抽出した証明書が保証するコードと、実際の生成コードの一致を示します。各末端には停止予算と多項式時間の証明が付きます。二つの生成コードは異なる対象を攻撃する別々のプログラムなので、両方を一つの機械で実行することや、その時間を単純に加算することを要求しません。同じ仮定を複数の枝で使う場合も、それぞれの使用を別々の末端として保持します。

優位性の上界は `LossTree` に保持します。一前提の節点は損失関数の適用、二前提の節点は二つの損失付き上界の和です。`MultiTree.advantage_le` は、各仮定の具体的な上界を与えた場合の導出全体の上界を示します。`loss_negligible` は、末端の上界がすべて無視できるなら全体も無視できることを示します。具体的な共通上界を与えるこの定理と、共通上界を要求しない `sound` は区別します。

`CompilerTree.run_substitute` と `MultiDerivation.substitute_run` は、仮定を別の導出で置き換えた場合、各末端の生成コードを入力として置換先の生成計画を実行することとの一致を示します。`loss_substitute` と `LossTree.eval_substitute` は、置換先の損失の式を元の式に代入した上界との一致を示します。一前提の導出は `ofUnary` で取り込め、`ofUnary_run` は元の一つの生成コードの保存を証明します。従来の正規形定理は一前提の断片について保持します。拡張後の抽出結果は複数の末端を持ち得ます。

`Foundation/Examples/MultiAssumption.lean` は、要求を false、ランダムな真偽値、true にした三つの実験を使います。二前提の公開規則から二つのコードを生成し、右の枝だけの命令追加と仮定の置換を実行で確認します。反復した仮定の位置も保存するテストを含みます。また、端点の優位性が1で、一方の隣接する確率差が0になる例により、一方の項を一般に捨てられないことを確認します。これらは帰着の検証例であり、具体的な暗号方式の安全性の主張ではありません。

## ElGamal への接続と保証の範囲

`ElGamal.Logic.derivation` は、写したインスタンスの族についての DDH 困難性を唯一の安全性の仮定として使います。`derivation_compiler_run` は、生成コードが既存の `simulatorCode` と一致することを証明します。`secure_of_ddh` は、論理の一般的な健全性定理から既存の安全性輸送を再構成します。

`ElGamal.Logic.language` は、正規化コードと乗算コードを有限プログラムとして受け取ります。意味論の証明を含む構造体は、実行用の言語に渡しません。

`ElGamal.PrimeOrderRepresentation.logicCompiler` は、具体的な正規化コードと乗算コードだけから作る計算可能なコンパイラです。`logicDerivation` も計算可能な定義であり、型付けの証明だけで既存の意味論に接続します。`logicDerivation_compiler` は、そのコンパイラが `logicCompiler` と一致することを証明します。`secureINDCPA_of_secureDDH_logic` には外部の実装引数は残らず、DDH の安全性が暗号学的仮定として残ります。

ガード変換のコード生成には、末尾再帰の `GuardedCompiler.blocksTR` を使用します。末尾再帰では、再帰呼び出しの後に処理を残さず、未完了の呼び出しの積み重なりを抑えます。`blocks_eq_blocksTR` は、元の `blocks` と全入力で同じ命令列を生成することを証明します。`csimp` の登録により、証明では元の定義を保持し、実行時には証明済みの実装へ置き換えます。`Foundation/Examples/GuardedCompilerExecution.lean` は、公開された `blocks` 関数を通して、10万命令から680万命令を生成する実行テストを含みます。命令列の長さ、先頭と末尾の配置、範囲外の分岐先の変換を確認します。

具体的な ElGamal の機械コードをすべて展開すると、多段のコード生成で非常に大きなプログラムになります。末尾再帰への変更は、生成する命令数を減らしません。`CompactProgram` は、命令列の長さを保持し、指定された位置の命令だけを構成する共有表現です。元の命令列は型と消去される証明にだけ現れます。連結、反復、命令の写像、サブルーチン化、ガード変換を、共有表現を組み合わせることで構成できます。

`compact_program` は、プログラムの定義をこの表現へ変換する証明生成タクティクです。アドレス計算の内部に隠れた命令列の長さも、証明付きの長さへ置き換えます。閉じた部分は補助定義として一度構成し、参照を共有します。生成する補助定義は Lean のカーネルで検査されます。対応していない操作にはエラーを返すため、任意の Lean プログラムを変換できるとは主張しません。

`PrimeOrderCompactCode.lean` の `compactCompile` は、既存の具体的な ElGamal コンパイラの共有表現を返します。`compactCompile_length` は任意の入力コードに対する命令数の式を証明し、`compactCompile_lookup` は任意の位置で元の生成コードと同じ命令を取得することを証明します。`CompactProgram.next_eq` は、範囲外での停止とランダムな分岐を含め、元の機械の一歩と一致することを証明します。元の機械の命令数や停止予算を変更するものではありません。共有表現の命令取得にかかるホスト上の時間・メモリは、別の費用です。

`Foundation/Examples/CompactProgram.lean` は、小さな複合コードの全命令と境界を元のコンパイラと照合し、46億2400万69命令のコードについて、展開せずに長さ・中間の命令・末尾・範囲外を取得できることを確認します。

具体的な固定コードの命令数は、正規化が `2,171,977,742`、乗算が `78,615` です。入力コードの長さを `n` とすると、帰着全体は `136n + 147,699,834,040` 命令です。`Foundation/Examples/ElGamalCompactProgram.lean` は、空の入力コードと一命令の入力コードについて、この数値、先頭・末尾・範囲外、および空のテープからの一歩を実行で確認します。

空の入力コードの全出力を連結リストとして展開する場合、64ビット環境でリストのセルを24バイト（ヘッダ8バイトとポインタ2個）とすると、セルだけで `3,544,796,016,960` バイト、約3.54 TBになります。命令オブジェクトなどの費用は含めません。共有表現での数値と境界の取得は、この開発環境で9.1秒、プロセス群の最大常駐メモリ3,604.5 MiBで完了しました。これは `lake env lean` の読み込み・評価・公理依存の表示を含む0.5秒間隔の実測であり、共有表現そのもののメモリ上界の証明ではありません。

停止予算は、生成機械の総入力ビット長に対する保証です。安全性パラメータに対する効率性は、各攻撃者の範囲が保持するプロトコル入力長の条件と合わせて扱います。外部の入出力解釈の処理費用、コンパイラ自身の実行時間、期待時間の機械モデルとの同値性は、この論理では証明しません。

## 資源上界を指定した安全性

`Semantics/Machine/ResourceSecurity.lean` の `ResourceBounds` は、総入力ビット長に対する実行ステップ数 `steps` と、安全性パラメータに対する入力ビット長 `inputLength` を保持します。具体的な上界は多項式である必要はありません。`Within` は、一つの有限プログラムによる攻撃者の族の実現、すべての入力とランダムな分岐に対する停止、およびすべての要求の入力長を要求します。停止予算の選択で攻撃者の振る舞いを変えられないことは、既存の燃料独立性の定理で保証します。

`ResourceSecure` は、この資源条件を満たすすべての攻撃者の族に共通する優位性の上界を述べます。既存の `BoundedByOnWithin` を使うため、優位性の意味は各 `CryptoGoal` の定義に従います。`ResourceSecure.mono` は、攻撃者に許す資源を減らし、優位性の上界を増やすと安全性が保持されることを示します。資源を増やした場合に攻撃者の範囲が広がることは `Within.mono` で証明します。その証明では、増やした停止予算でも同じ攻撃者を実現することを確認します。

`ppt_iff_exists_resources` は、二つの上界が多項式である資源条件の全体が、既存の多項式時間の攻撃者の範囲と一致することを示します。`securePPT_iff_all_resources` は、それらすべての資源条件についての漸近的安全性と、多項式時間の攻撃者全体についての安全性の同値を示します。攻撃者ごとの無視できる上界を、共通する一つの無視できる上界に置き換えることはしません。

この段階の実行時間は、一つの要求に対する機械の応答のステップ数です。外部の実験、入出力の解釈、複数の問い合わせ全体の費用は含めません。安全性パラメータに対する時間を得るには、入力長の上界と実行ステップ数の上界を接続する必要があります。問い合わせ回数の上界、帰着後の共通資源上界、および具体的な共通鍵暗号の安全性実験は、追加の定義と証明を要します。

`Foundation/Examples/ResourceSecurity.lean` は、実際の二ステップの確率的プログラムが資源条件を満たすことと、停止予算を増やしても同じ攻撃者を実現することを確認します。必要な入力長より小さい上界では、攻撃者が一つも許容されないことも確認します。

## 帰着による共通の資源上界と優位性の変換

`Semantics/Machine/ResourceReduction.lean` の `ResourceProgramReduction` は、帰着前と帰着後の資源上界を指定した証明書です。元の上界で停止するすべての有限プログラムについて、同じコンパイラの出力が帰着後の共通上界で停止することを要求します。また、生成コードが意味論上の帰着を実現することと、写した実験のすべての要求が入力長の上界を満たすことを要求します。外部の入出力解釈の費用と問い合わせ回数は、この証明書の範囲に含めません。

`mapWithin` は、帰着先の攻撃者の機械表現をコンパイラの出力として構成します。`resourceSecure` は、帰着先の共通資源上界での安全性から、帰着元の資源上界での安全性を導きます。帰着先の優位性の上界が `ε n` の場合、帰着元の上界は `r.loss.eval n (ε n)` です。この具体的な定理は、資源の多項式性や損失による無視できる上界の保存を要求しません。

`comp` は、中間の資源上界が一致する二つの証明書を合成します。コードは元の帰着、次の帰着の順に生成します。優位性の上界には、次の帰着の損失、元の帰着の損失の順に関数を適用します。`comp_run` は、この合成が実際の生成コードの逐次合成と一致することを証明します。

`ofSimulation` は、既存の機械シミュレーションと、共通する停止予算の上界および入力長の上界から証明書を構成します。`CertifiedReduction.uniformResources` は、小さな論理の既存の帰着証明書を接続します。この接続では、元のステップ数の上界が多項式であることを要求します。さらに、元の予算で停止するすべての `BoundedProgram` に対する共通の帰着後の上界を、明示的な証明として要求します。個々のプログラムについての多項式時間性だけから、共通する上界を推論しません。

`AdvantageBound.affine` は、自然数値の係数と加算する誤差の関数による `c n * ε n + δ n` の上界です。`resourceSecure_affine` は、この形式の具体的な安全性輸送を示します。係数が多項式で、加算する誤差が無視できる場合には、`affine_preservesNegligible` が漸近的安全性への接続を保証します。

`Foundation/Examples/MachineResourceReduction.lean` は、実際のガード変換について共通資源上界を構成します。二ステップの元の機械に対し、生成機械のステップ数を総入力ビット長 `m` に対する `1125 * (m + 1)` 以下で保証します。入力長の条件は保持します。また、既存の論理の命令追加の証明書を接続し、ガード変換との合成順序と安全性の輸送を確認します。検証用に恒等帰着の優位性の上界を緩めた例では、実際の生成機械に対する資源の保証と、乗算・加算を含む `2 * ε n + 1/8` の上界を接続します。

## 問い合わせ回数の上界を含む安全性

`Semantics/Oracle/Program.lean` の `CryptoOracle.Program` は、結果を返す処理、オラクルへの問い合わせ、局所的な公平な乱数の三つの構成子を持ちます。問い合わせの継続処理は返答を受け取るため、返答に応じて次の要求を選べます。`run` は、オラクルが返す次の状態を次の問い合わせに渡します。オラクルの状態を呼び出しごとに初期化しません。実行結果は、最終結果、最終状態、および要求と返答の記録を保持します。

`BoundedQueries` は、すべての返答と局所的な乱数の選択について成立する問い合わせ回数の上界です。`trace_length_le` は、実行結果の分布の台に属するすべての記録の長さが、その上界以下になることを証明します。`mono` は、上界を増やした場合の保存を示します。局所的な乱数を引く処理は、オラクルへの問い合わせとして数えません。問い合わせが0回の場合には、`zero_run_result_eq` が結果の分布はオラクルと初期状態に依存しないことを証明します。

`Semantics/Oracle/QuerySecurity.lean` の `Protocol` は、公開されたインスタンスと、二つのオラクルの実験の解釈を分けます。任意の確率関数を機械の入力に符号化することは要求しません。`goal` は、同じ問い合わせ構文を二つのオラクルに対して実行し、true を返す確率の絶対差を優位性とします。内部状態を攻撃者に渡すことはありません。`queryClass` は、各安全性パラメータについて指定された問い合わせ回数以内の攻撃者を認めます。`zeroQueries_secure` は、問い合わせが0回なら優位性が0であることを示します。

`ResourceQuerySecure` は、同じ攻撃者の族について、前段階の機械資源の条件と問い合わせ回数の条件の両方を要求します。`QueryReduction` は、共通する機械資源上界の証明書と、意味論上の帰着が問い合わせ回数の条件を保存する証明を保持します。`secure` は、帰着先の資源・問い合わせ回数・優位性の上界から、帰着元の安全性を導きます。`comp` は、中間の資源上界と問い合わせ回数の上界が一致する証明書を合成します。問い合わせ回数の変換は、個別の帰着について明示的に証明する必要があります。

`Foundation/Examples/OracleQueries.lean` は、一回目の返答を二回目の要求にする攻撃者を検証します。二つのオラクルについて、異なる問い合わせの記録と、状態が二回更新されたことを確認します。二回の上界では認められ、一回の上界では認められないことを証明します。この攻撃者の優位性が1であることも証明するため、問い合わせの証明が実際に安全性実験で実行するプログラムと接続していることを確認できます。問い合わせなしの場合の完全な識別困難性と、問い合わせの上界を変える帰着の合成も検証します。

この定義では、実験全体の問い合わせ回数を保証します。`ResourceQuerySecure` の時間は、既存の入出力解釈に対する一つの要求への応答のステップ数です。攻撃全体の実行時間を扱う場合は、次の `WholeSecure` と対話機械の証明書を使います。

## 有限の対話機械による攻撃全体の時間

`Semantics/Oracle/InteractiveMachine.lean` は、既存のビット機械の命令と、オラクル呼び出しの命令からなる有限コードを定義します。一つのコードが、返答を受けた後も同じプログラム位置と作業テープの状態を使って実行を続けます。任意の Lean の継続関数を攻撃者の実行処理として呼び出しません。公開入力は実験側が初期テープに載せます。攻撃者がその入力を読む処理と、要求を組み立てる処理は、有限コードの命令として実行します。

`call` は、出力テープの現在の位置から最初の空白までを要求として読みます。要求の読み出しとバッファの反転、返答のセルごとの書き込み、ヘッドの移動、巻き戻し、復帰を、それぞれ明示的な遷移として数えます。オラクル内部の計算は実験側の処理であり、呼び出し自体を1ステップとして数えます。最終結果の読み出しも1ステップです。時間の単位は、この対話機械の命令または固定サイズの制御操作の遷移数です。ホスト上のインタプリタや物理CPUの時間との同値は主張しません。問い合わせの記録は観測用の情報であり、有限コードから秘密状態や記録に直接アクセスする命令はありません。

`transition` は計算可能な次の遷移を構成します。`step` はその同じ遷移に、公平な局所乱数と確率的なオラクルの意味を与えます。`simulate` は、決定的な検証用オラクルと指定した乱数の値に対して、その遷移を実行します。完了後のパディングを含めず、使用したステップ数を返します。`HaltsWithin` は、指定したステップ数の時点ですべての分岐が本当に完了していることを要求します。燃料を使い切っただけの未完了状態は、この条件を満たしません。`eval_stable` と `eval_eq_of_halts` は、正しい停止上界を増やしても実行結果の分布が変わらないことを証明します。

`Semantics/Oracle/WholeAttack.lean` の `WholeInterface` は、公開入力と要求・返答の有限ビット列による表現を指定します。`WholeWitness` は、安全性パラメータの外で固定した一つの有限コードを保持します。二つの実験のそれぞれについて、全体の停止上界、実際の問い合わせ回数の上界、および元の型付き実験との実現の証明を要求します。実現は結果の真偽値だけでなく、要求と返答の全記録および最後のオラクルの状態の分布を保存します。`trace_length_le` は、元の実験の問い合わせ記録にも回数の上界が成立することを示します。

`WholeSecure` は、全体の時間 `t n` と問い合わせ回数 `q n` を満たす攻撃者についての共通する優位性の上界です。`WholeReduction` は、実行用の有限コードのコンパイラと、その出力を正確に保証する証明書の変換を保持します。`secure` は、全体の時間・問い合わせ回数・優位性の上界を運びます。`comp` は、証明書とコード生成を同じ順序で合成します。`WholeWitness.mono` は、時間と問い合わせ回数の上界を増やしても同じ有限コードと同じ実験の分布を保持することを証明します。個々の帰着に必要な停止・実現の証明を自動で合成・発見する機能は、この定義の内容ではありません。

`Foundation/Examples/WholeOracleAttack.lean` は、前段階の二回の適応的な問い合わせを、4命令の有限コードで実装します。一回目の返答を二回目の要求にする処理は、対話機械の返答転送と次の `call` で行います。要求と返答の転送を含めた全体の時間は25ステップです。実行テストとカーネルで検査する確率分布の等式の両方で、二つの実験について結果、全記録、状態が一致することを確認します。このコードは24ステップでは未完了です。局所的な公平な乱数を使うコードについても、両方の分岐が3ステップで完了することを確認します。具体的な共通鍵暗号方式の安全性は、この検証例とは別に登録・証明する必要があります。

## PRG から作る一回限りの共通鍵暗号

擬似乱数生成器（PRG）の識別困難性を仮定し、一度だけ暗号化する共通鍵方式の安全性を導く部品を追加しました。暗号化は `G(k) XOR m`、復号も同じ鍵による XOR です。XOR はビットごとの排他的論理和です。鍵はこの暗号化のために一様に選びます。

| ファイル | 役割 |
|---|---|
| `Constructions/Symmetric/OneTimePad.lean` | 長さ付きビット列、XOR、一様乱数、ワンタイムパッドの正しさと完全秘匿性を証明します。 |
| `Constructions/Symmetric/PRGEncryption.lean` | PRG と一回限りの暗号の識別実験、および二つの帰着による優位性の上界を定義します。 |
| `Crypto/Semantics/Machine/Masking.lean` | ビット単位の前処理と既存の有限攻撃コードを組み合わせる実行機械を定義します。 |
| `Constructions/Symmetric/PRGResource.lean` | 生成コードの停止、意味の実現、問い合わせ数、具体的資源上界と安全性の輸送を証明します。 |
| `Examples/PRGEncryption.lean` | 帰着の実行、停止時間の境界、両方の乱数分岐、攻撃者の範囲が空でないことを確認します。 |

ワンタイムパッドの `ciphertext_uniform` は、平文を固定しても暗号文が一様分布になることを等式として証明します。`perfect_secrecy` は、任意の確率的な観測者について左右の平文から得る観測分布が等しいことを証明します。計算量の制限は不要です。長さゼロも含みます。

PRG の候補を表す `Generator` は、種の長さ、出力の長さ、種から出力への写像を保持します。帰着定理は任意の長さに適用できるため、種より長い出力という条件は構造体に強制していません。伸長する PRG を使う利用者は、その長さの条件も指定できます。この実装は特定の PRG の安全性を証明していません。

`encryptionGoal` の公開インスタンスは、等長の二つの平文です。攻撃者はパラメータ、両方の平文、暗号文を受け取ります。左右の実験は、そのどちらかを新しい一様な種で一回暗号化します。平文は挑戦の前に固定されます。適応的な暗号化問い合わせを複数行う安全性や、同じ鍵を複数回使う安全性はこの定理の対象ではありません。

`prgGoal` は、生成器の出力と、同じ長さの真の一様乱数を識別する実験です。帰着が二つの平文を読めるよう、同じ公開インスタンスを持ちます。挑戦の分布は公開平文に依存しません。公開入力の族そのものを読む命令はありません。

帰着は左右の平文それぞれについて一つずつ生成します。`reductionPrograms` は元の有限攻撃コードだけから二つのコードを返します。各コードは、固定された側の平文と PRG の挑戦を XOR し、元の攻撃コードを実行します。停止予算、証明、インスタンスの族、生成器の意味はコード生成の引数に入りません。

この一回限りの実験では、既存のビット機械に有限の前処理制御を接続します。前処理制御は公開入力を一ビットずつコピーし、平文と挑戦の一組のビットずつ XOR を取り、元の攻撃への入力を一セルずつ用意します。各制御遷移は固定個数のセルを扱います。任意の Lean 関数を攻撃者の実行命令として呼び出す構文はありません。生成コードはこの機械の `Code.masked` と既存の有限 `Machine.Program` の組であり、前処理を既存の命令列だけに変換したものではありません。安全性論理の推論規則は変更せず、`CryptoGoal`、`AdversaryTransform`、資源に制限した安全性の定義を再利用しています。

公開入力の先頭部分は、安全性パラメータの単項符号と、長さを付けた二つの平文です。その長さは `n + 4L(n) + 3` ビットです。前処理では先頭部分のコピー、XOR、入力のセル転送を全て数えます。元の攻撃時間が `t(n)` 制御遷移で、暗号文長が `L(n)` ビットなら、各帰着コードの上界は次の値です。

```text
targetTime(n) = t(n) + 2n + 10L(n) + 9
PRG への問い合わせ回数 = 1（各帰着について）
暗号の識別優位 ≤ 左の帰着の PRG 識別優位 + 右の帰着の PRG 識別優位
```

時間の単位は、既存ビット機械の一命令または固定個数のセルを扱う前処理制御の一遷移です。実機の CPU 時間との対応は主張していません。実験開始時の入力の用意と、PRG の内部評価は実験側の仕事です。帰着側で行う XOR と入力転送は時間に含めます。

`NativeWitness` は、全ての長さが正しい挑戦入力と、全てのネイティブ乱数分岐での停止を要求します。`ChallengeWitness` は、前処理を含む同じ要求と、確率分布の完全な実現を要求します。生成器の出力でだけ停止するという弱い証拠にはしていません。`emitted_halts` と `emitted_realizes` は実際に生成したコードについての保証です。後者は結果と挑戦の記録の同じ分布を証明します。`emitted_queries` は実行分布の全ての台に属する結果で、問い合わせ記録の長さが一であることを証明します。ネイティブ攻撃コードは PRG を問い合わせる命令を持たないため、追加の挑戦を取得できません。

PRG の全ての許された攻撃の識別優位が、上の時間上界で `ε(n)` 以下なら、`resource_secure` は元の攻撃時間で暗号の識別優位が `2ε(n)` 以下であることを導きます。確率差を直接使うライブラリの規約で、この係数を証明しています。`reductionTime_polynomial` は暗号文長と攻撃時間の多項式上界から、帰着時間の多項式上界を導きます。`resource_secure_asymptotic` は、各帰着の個別の無視できる上界から暗号の漸近的安全性を導きます。

実行例は、暗号文の最初のビットを読む元の攻撃が 14 遷移、左右の帰着がそれぞれ 43 遷移で停止することを確認します。右の帰着に 42 遷移しか与えない場合は未停止です。例の生成器は最初の出力ビットが常にゼロとなる意図的に安全でないものです。生成器の安全性の仮定を省略して暗号が安全だと結論する例にはしていません。

## 実行機械の一般化

`CryptoLogic.General` は、実行機械を指定して同じ安全性論理を使うための共通基盤です。推論規則は仮定の使用、単一の帰着による輸送、二前提の帰着です。各帰着には入力機械と出力機械の型が付きます。中間の機械が一致する帰着だけを合成できます。一つの導出から、異なる機械で動く複数の帰着コードを生成できます。

[Execution.lean](../Foundation/Crypto/Logic/General/Execution.lean) の `CodeSystem` は、機械の識別子、コード、登録したコンパイラの構文を指定します。これらには自然数への符号化と復号を与えます。`Compiler` は恒等、登録したコンパイラ、合成からなる構文です。今回の具体的な実装では、有限の構文と元のコードだけから出力コードを計算します。

`ExecutionInterface` は、資源の型、停止と資源上界を表す `ExecutesWithin`、攻撃者の分布との一致を表す `Realizes` を指定します。資源と意味論の証拠は、コンパイラの入力には入りません。`CertifiedTransform` と `CertifiedReduction` は、元のコードの証拠を出力コードの証拠へ変換します。`code_eq` は、その出力コードが登録したコンパイラの生成コードと厳密に等しいことを要求します。抽象的なインターフェースを与えるだけでは、具体的な停止証明や資源上界は得られません。

[Backends.lean](../Foundation/Crypto/Logic/General/Backends.lean) は、次の既存実装に接続します。

| 機械 | 保持する実行保証 |
| --- | --- |
| ビット機械 `Machine.Program` | 全入力・全乱数分岐での停止、多項式の停止予算、既存インターフェースの分布との一致 |
| 前処理機械 `Machine.Masking.Code` | 全ての長さが正しい挑戦入力での停止、XOR と入力転送を含む時間上界、既存の挑戦実験の分布との一致 |
| 対話的な問い合わせ機械 `Interactive.Code` | 全ての応答環境での停止と問い合わせ上界、結果・状態・問い合わせ記録を含む分布との一致 |

前処理機械と問い合わせ機械では、時間と問い合わせの上界を安全性の対象に固定します。証拠側の資源値は `Unit` ですが、停止条件と上界が省略されるわけではありません。ビット機械では、証拠側に停止予算の関数を保持します。異なる機械の時間単位の同値性や、任意の機械間の自動変換は主張しません。

[Derivation.lean](../Foundation/Crypto/Logic/General/Derivation.lean) は、機械の型を持つ純粋な帰着計画と、意味論による型付けの証拠を分けます。`Derivation.run` は仮定の位置、出力機械、生成コードを返します。`substitute` は仮定を別の導出で置換します。`sound` は文脈の全仮定の安全性から結論の安全性を導きます。空の文脈から導出を構成できないことも証明しています。

[Extraction.lean](../Foundation/Crypto/Meta/General/Extraction.lean) は、全ての仮定の使用に対応する帰着と損失上界を取り出します。同じ仮定を複数回使った場合は、各使用を保持します。`extract_emitted` は実際に生成するコード列と、証明した帰着のコード列の一致を示します。各枝には停止・資源・分布の証拠が付きます。`advantage_le` は各仮定の優位性上界から導出全体の上界を与えます。仮定の置換による損失の合成も証明しています。

[Legacy.lean](../Foundation/Crypto/Logic/General/Legacy.lean) は、既存の単一仮定・複数仮定の API を共通基盤へ変換します。旧 API は引き続き利用できます。変換前後の生成コードと、証明木の損失式の一致を証明しています。

[GeneralExecution.lean](../Foundation/Examples/GeneralExecution.lean) は、ビット機械と前処理機械へ分岐する導出、問い合わせ機械の帰着、仮定の置換、旧 API からの変換を検査します。コード生成は `#eval` でも確認します。異なる機械へ分岐する例は元の仮定も保持する検査用の帰着であり、PRG 暗号の安全性定理を新しい論理に登録した例ではありません。PRG 暗号の登録は、次節の専用モジュールで行います。


## PRG 暗号の二前提帰着の登録

[PRGLogic.lean](../Foundation/Constructions/Symmetric/PRGLogic.lean) は、一回限りの PRG 暗号の帰着を `CryptoLogic.General` に登録します。PRG は擬似乱数生成器です。結論はビット機械による暗号の識別困難性で、二つの前提は前処理機械による PRG の識別困難性です。両方の前提で同じ公開平文の族と同じ時間上界を使います。

`certificate` は、既存の有限 XOR 制御による左右の帰着を二前提の帰着としてまとめます。`signature` はその帰着を論理の推論規則に接続します。`derivation` は二つの仮定の位置を使い、左右の帰着コードを生成します。`sharedDerivation` は仮定の置換により、同じ PRG 安全性の仮定を二回使う導出を構成します。置換後も二つのコードと二つの損失項を保持します。

`run` と `shared_run` は、生成コードが既存の `reductionPrograms` と厳密に等しいことを証明します。元のコードだけがコード生成の入力です。生成器の評価、意味論上の攻撃者、停止証明、時間予算をコード生成時に評価する必要はありません。`extract_emitted` と `shared_extract_emitted` は、生成コード列と論理から抽出した証明付きの帰着コード列の一致を示します。

`emitted_halts` と `emitted_output` は、一般化した実行証明から、生成コードの全挑戦入力・全乱数分岐での停止と分布の実現を導きます。`emitted_realizes` は任意の挑戦分布について、結果と挑戦記録の分布が意味論上の帰着と一致することを証明します。`emitted_queries` は実験の全ての出力で、各帰着の挑戦取得が一回であることを証明します。帰着の時間上界は引き続き `t(n) + 2n + 10L(n) + 9` 遷移です。

`secure` は共通論理の健全性定理を使い、一つの PRG 安全性の仮定から暗号の安全性を導きます。`bounded` は生成計画と一致する明示的な証明木に共通の優位性上界定理を適用し、左右の上界 `ε₀(n)` と `ε₁(n)` の和を導きます。`bounded_twice` は両方に同じ上界を与え、`2ε(n)` を導きます。PRG の安全性は引き続き前提です。対象は公開された等長の平文対を使う一回限りの実験であり、適応的な複数回の暗号化は対象に含めません。

[PRGLogic の実行例](../Foundation/Examples/PRGLogic.lean) では、導出から実際にコードを生成し、仮定の置換後も左右のコードが保持されることを検査します。意図的に安全でない既存の検査用生成器を使い、左右の生成コードが43遷移で停止し、42遷移では未停止になることを確認します。別の乱数を使う固定コードについては、任意の生成器・公開入力の族での停止と分布の実現も検査します。

## 共通する資源安全性と導出のメタ定理

[ResourceSecurity.lean](../Foundation/Crypto/Meta/General/ResourceSecurity.lean) は、機械ごとの実行保証を保持したまま、具体的な優位性上界を扱う共通 API を提供します。`SecurityObject.Bounded F ε` は、対象の資源制約付き攻撃者全てに、共通の上界 `ε` が成立することを表します。単一の帰着、二前提の帰着、一般の導出について、損失付きの上界を運ぶ `bounded` 定理を用意しています。上界の緩和と、無視できる共通上界から漸近的な安全性への接続も証明します。対象の資源制約と時間の単位は、各実行インターフェースの定義を使います。

`Derivation.runWitnesses` は、元の攻撃者の実行証拠を受け取り、各仮定の使用に対応する `CertifiedOutput` の列を返します。各要素は、文脈での仮定の位置、変換後の攻撃者、生成コード、対象機械の資源値、停止と資源上界、分布の実現、攻撃者クラスへの所属を保持します。対象のインスタンスの族は、その文脈位置の族と一致します。`runWitnesses_emitted` は、この証拠付きの列から取り出すコードが通常の `Derivation.run` の結果と厳密に一致することを証明します。証拠の抽出は解析用の非計算的処理です。通常のコード生成は引き続き純粋な有限構文だけを使います。

`Derivation.Analysis` は、導出の生成計画と一致する特定の登録済み証明木を指定するための証明書です。同じ生成計画に異なる損失の証明が対応する可能性があるため、コードの一致だけから損失式の一意性は仮定しません。この API では、指定した証明木の損失式に対して `bounded` を適用します。`Analysis.runWitnesses` は、同じ証明木から資源証拠を取り出します。この場合も生成コードとの一致を証明します。`Analysis.substitute` は指定した証明木同士を使って仮定を置換します。`loss_substitute` は、その損失式が元の式への置換と一致することを証明します。PRG 暗号の `analysis` と `sharedAnalysis` をこの API に接続し、同じ仮定を二回使う場合の損失が `2ε` になることを証明しています。

[Metatheory.lean](../Foundation/Crypto/Meta/General/Metatheory.lean) は、登録済みの型付き証明木から実行計画を構成する `ofTree` と、登録済み証明木の存在と導出の存在が同値であることを提供します。これは登録した推論規則に対する対応であり、任意の意味論上の安全性含意を導出できるという完全性ではありません。一般の二前提帰着には二つの前提が必要なので、一つの仮定への帰着経路だけに置き換えることも主張しません。

`Derivation.substitute_run` は、仮定の置換後の実行が各末端での型の合う順次実行と一致することを示します。生成コード列と実行証拠の列は空ではなく、その長さは使用した仮定の出現数と一致します。同じ位置を二回使う場合も二つの出現を保持します。

[GeneralResources.lean](../Foundation/Examples/GeneralResources.lean) は、ビット機械と前処理機械への分岐、対話機械の証拠付き出力、一つの PRG 仮定を二回使う場合のコード列・証拠数・損失式を検査します。新しい暗号方式の安全性を前提なしに結論する検査にはしていません。

## 帰着コンパイラの正規化

[Normalization.lean](../Foundation/Crypto/Meta/General/Normalization.lean) は、恒等と合成を含む帰着コンパイラを、登録済みの基本コンパイラの順次列へ整理します。`CompilerChain` は、各基本コンパイラの入力と出力の機械が一致する場合だけ接続できる構文です。`Compiler.normalize` はこの列から、恒等の合成節点を含まない右結合のコンパイラを構成します。空の列は恒等、要素一つの列はその基本コンパイラになります。

正規化は、登録済みコンパイラの適用順序を保持します。基本コンパイラの内部の機械命令列は展開・変更しません。`normalize_run` は任意の元のコードについて、生成するコードが正規化前と厳密に一致することを証明します。`normalize_idempotent` は一回の正規化後に構文が固定点になることを示します。恒等の挿入と、合成の結合の仕方の変更についても、正規化後の構文の一致を証明します。異なる基本コンパイラが偶然同じコードを生成する場合に、それらを同一視する正規化ではありません。

`Derivation.normalize` は、導出に保存したコンパイラの列だけを正規化します。型付けの証明と元の帰着計画は保持します。仮定の位置・使用順序・出現数は変わりません。`normalize_loss` と `normalize_runWitnesses` は、損失式と、資源値・停止・分布の実現を含む証拠付き出力の列がそのまま保存されることを証明します。明示的な証明木を使う `Analysis` についても、同じ保存定理を提供します。

`normalize_substitute_run` は、仮定の置換の前後どちらで正規化しても、生成コードが一致することを示します。置換処理は元の帰着計画からコンパイラを構成するため、最終的なコンパイラ列を正規化したい場合は全ての置換の後に `normalize` を適用します。正規化はコード生成用の構文の整理です。生成された機械コードの実行時間が短くなるという主張は含めません。

[GeneralNormalization.lean](../Foundation/Examples/GeneralNormalization.lean) は、ビット機械から前処理機械への帰着で、恒等を挿入した9節点の構文が3節点に整理されることを検査します。PRG 暗号の左右の帰着は、それぞれ3節点から1節点になります。同じ仮定への二つのコードは両方とも保持されます。対話機械でのコード生成と、元の命令列が厳密に保存されることも検査します。

## 任意の固定段数と可変段数のハイブリッド

[FiniteHybrid.lean](../Foundation/Crypto/Meta/General/FiniteHybrid.lean) は、既存の二前提規則を繰り返し使い、任意の正の有限段数の導出を構成します。対象はビットを挑戦として渡す実験です。隣接する各実験対に、元の攻撃と同じ有限機械コードを帰着として渡します。`run` は仮定の位置と生成コード列の厳密な一致を証明します。`bounded` は各段階の上界の和を導きます。全段階に共通する上界を使う `bounded_uniform` と、実験を変更しない場合の `bounded_zero` もあります。`analysis` は各枝の資源証拠と損失解析を既存の API に接続します。`emitted_halts` は全ての生成コードに元の停止上界を引き継ぎます。`total_budget` は、各段階のコードを別々に実行した場合の上界の合計が、段数と元の上界の積になることを証明します。

[CountedLoop.lean](../Foundation/Crypto/Semantics/Oracle/CountedLoop.lean) は、一つの固定された8命令のコードで、入力に指定した回数だけビットの問い合わせを行います。各返答を次の要求として使います。`run` は状態・結果・問い合わせ記録を含む分布の一致を証明します。`halts` と `queries` は任意の確率的な返答に対して、問い合わせ回数 `q` の場合に `14q+6` 遷移以内で停止し、記録にちょうど `q` 回の問い合わせがあることを証明します。`profile_halts` は、回数を安全性パラメータの関数 `q(n)` としてもコードが変わらない場合です。`profile_time_polynomial` は `q(n)` の多項式上界から時間の多項式上界を導きます。これはビットの応答を扱う実行核です。任意長の暗号文を扱う帰着コンパイラの証明には、別途、メッセージの処理と転送の証明が必要です。

[UniformHybrid.lean](../Foundation/Crypto/Meta/General/UniformHybrid.lean) は、可変段数 `q(n)` の各段階に共通する上界 `ε(n)` がある場合に、両端の確率差が `q(n)ε(n)` 以下になることを証明します。`negligible` は、`q(n)` が多項式で抑えられ、`ε(n)` が無視できる場合に、両端の確率差も無視できることを示します。各固定位置に対する無視できる上界だけでは、この共通上界の前提を満たしません。数値定理に加えて、`loopProbability` は固定された8命令の実行の受理確率を定義します。`executed_bounded` と `executed_negligible` は、この実行の各段階の共通上界から両端の上界を導きます。`executed_resources` は、同じコードが全ての実験で停止し、指定した回数だけ問い合わせることを証明します。ハイブリッドの段数と問い合わせ回数は別々の関数として指定できます。実験を構成して隣接する実験の上界を証明する作業は、この定理の前提です。

[FiniteHybrid の例](../Foundation/Examples/FiniteHybrid.lean) は4段階のコード生成、正規化後の一致、任意段数の出力数と損失を検査します。[CountedLoop の例](../Foundation/Examples/CountedLoop.lean) は、0回、1回、4回の実行を検査します。返答を反転する検査用の環境を使い、4回の場合は要求が直前の返答に応じて変わることを確認します。4回は62遷移で完了し、61遷移では未停止です。

## 擬似乱数関数の実験定義

[PRF.lean](../Foundation/Constructions/Symmetric/PRF.lean) は、有限領域の擬似乱数関数の実験を定義します。実際の実験では鍵を一度だけ生成します。理想実験では一様な関数表を一度だけ選びます。両方とも実験中は同じ関数を使うため、同じ入力には同じ応答を返します。関数表全体の選択は確率分布の定義であり、帰着機械が実行する処理ではありません。`repeated_query` は同じ入力への二回の応答と記録の一致を証明します。`zero_queries` は問い合わせがない攻撃の出力分布が両実験で等しいことを証明します。

`QuerySecure` は問い合わせ回数だけを制約します。時間も制約する安全性は、後述の `PRFCounterResource` が定義する有限コードの攻撃者クラスと、共通の `Bounded`・`Secure` を使って指定します。

[PRFCounter.lean](../Foundation/Constructions/Symmetric/PRFCounter.lean) は、暗号化ごとにカウンターを進める方式と、その意味論上の帰着を定義します。カウンターの範囲を使い切った場合には暗号文を返さず、以前の値を再利用しません。`correctness` は復号の正しさを証明します。`simulation`、`real_simulation`、`ideal_simulation` は、適応的に平文を選ぶ攻撃について、帰着と元の暗号化実験の出力分布が等しいことを証明します。`queries` は帰着が問い合わせ回数を増やさないことを示します。`advantage_bound` は左右の PRF 優位性と理想暗号化の確率差を明示的に残します。この定理は理想暗号化の確率差を残した一般の上界です。次の専用モジュールで完全秘匿性を証明し、この項を除去します。帰着に含まれるカウンターと排他的論理和の操作は、後述の `CounterMasking` と `CounterWhole` で有限コードに接続しています。[検査例](../Foundation/Examples/PRFCounter.lean) は、容量が2回のときに3回目の暗号化要求を拒否し、PRF への問い合わせが2回以下になることを検査します。

[PRFCounterPrivacy.lean](../Foundation/Constructions/Symmetric/PRFCounterPrivacy.lean) は、理想暗号化の完全秘匿性を証明します。`uniform_resample` は、一様な関数表の一つの値を独立に選び直しても、表全体の分布が変わらないことを示します。`run_future_congr` は、使用を終えたカウンターの値が後の攻撃の出力に影響しないことを示します。これらを使う `ideal_fresh` は、単一のランダム関数を新しいカウンターに対して使う実験と、各成功時に独立な一様暗号文を返す実験の出力分布が等しいことを証明します。`ideal_privacy` は、適応的な平文選択と攻撃者の乱択を含め、左右の理想実験が厳密に等しいことを示します。容量ゼロ、平文長ゼロ、容量の枯渇も含みます。

`advantage_le_prf` は、暗号化の識別優位を左右二つの PRF 帰着の識別優位の和で抑えます。`query_secure` は、問い合わせ回数 `q(n)` での PRF の共通上界 `ε(n)` から、複数回暗号化の上界 `2ε(n)` を導きます。`query_secure_asymptotic` は、攻撃者ごとに異なる無視できる上界を許した漸近的な安全性を輸送します。これらの定理が制約するのは問い合わせ回数です。CPU 時間を制約した PRF 安全性の仮定で使う場合は、後述の `PRFCounterLogic.bounded` を使います。

[CounterMasking.lean](../Foundation/Crypto/Semantics/Oracle/CounterMasking.lean) は、元の有限対話コードと平文を選ぶ一つのビットから帰着コードを構成します。コードは自然数に符号化できます。容量とカウンターは単項表現のテープデータとして保持します。要求は左右の平文ビットを交互に並べたものです。制御部分は一対を選び、カウンターをセルごとに転送し、PRF 応答との排他的論理和をビットごとに計算します。返答は、成功を表すビット、単項カウンターの終端を含む表現、暗号文を連結したものです。容量の枯渇時には失敗を表すビットだけを返し、PRF に問い合わせません。

`select_eval`、`masking_eval`、各コピー・反転補題は、このコードの制御部分の遷移数と結果を証明します。`query_controller_eval` は、平文長が `L` ビット、カウンターが `i` セルの場合に、問い合わせの制御部分が `4L+2i+7` 遷移で返却データを構成することを示します。`deliver_eval` は、さらに一遷移で元の対話機械の応答転送処理へ戻ることを示します。[実行例](../Foundation/Examples/CounterMasking.lean) は、元の有限対話コードを包み、左右の平文選択、PRF の問い合わせ記録、返却する暗号文を検査します。両方の例は39遷移で完了し、38遷移では未停止です。一回ごとの証明は、後述の `CounterWhole.run` で元の攻撃の全実行に合成しています。

`query_success_eval` は、元の機械が問い合わせ待ちの状態にある場合について、容量の一セルの消費から元の応答転送への復帰までを `4L+2i+9` 遷移で証明します。元の問い合わせ記録には暗号文を、帰着の問い合わせ記録には元のカウンターでの PRF 要求と応答を保持します。`query_exhausted_eval` は、容量の枯渇時には二遷移で失敗応答を返し、カウンターと PRF 問い合わせ記録を変更しないことを証明します。

`decryptCiphertext` は、暗号文中の自然数のカウンターを検査して復号し、領域外のカウンターを拒否します。`oracle_correctness` は、暗号化が成功した全応答の復号が選択した平文になることと、容量の枯渇時の失敗が復号でも保持されることを証明します。公開容量テープの長さの上界と型付き実験との分布の一致は、次の資源証拠で扱います。


## 複数回暗号化の全実行と論理への登録

[CounterWhole.lean](../Foundation/Crypto/Semantics/Oracle/CounterWhole.lean) は、元の攻撃の暗号化オラクルを一遷移の能力として扱い、帰着コードの全実行との分布の一致を証明します。`Safe` は、元の攻撃が全ての実行分岐で停止することと、成功する要求が宣言した平文長の形式を満たすことを記述します。帰着コードの停止や正しさはこの前提に含めません。通常の元の実行の停止と各時点の要求の形式から `safe_of_source` で証拠を構成できます。`segment` は元の一遷移に対応する帰着の実遷移列を構成します。`run` はこれを合成し、元の状態・暗号文の記録・PRF の記録を含む分布全体の一致を証明します。元の局所乱数による両方の分岐も含みます。

元の時間上界を `t(n)`、平文長を `L(n)` とすると、帰着の時間上界は

```text
t′(n) = t(n) × (4L(n) + 2t(n) + 9)
```

です。`halts` はこの上界での全分岐の停止を証明します。`queries` は、元の暗号化問い合わせが `q(n)` 回以下なら、帰着の PRF 問い合わせも `q(n)` 回以下になることを示します。`budget_polynomial` は `t` と `L` の多項式上界から `t′` の多項式上界を導きます。オラクル内部の関数評価は実験側の能力であり、帰着の CPU 遷移数には含めません。要求と応答の転送、カウンターの処理、排他的論理和、元の攻撃の実行は計上します。

[PRFCounterResource.lean](../Foundation/Constructions/Symmetric/PRFCounterResource.lean) は、方式と時間・問い合わせ上界を指定した攻撃者クラスを定義します。一つの有限コードを選んだ後で、全ての安全性パラメータに対する停止と分布の一致を要求します。`SourceExecution` は元の実行の時間・問い合わせ上界と要求の形式を保証します。`SourceRealization` は元のコードが型付きの暗号化実験の出力分布を実現することを保証します。`compiled_execution` と `compiled_realization` は、この二つの元の証拠から、実際に生成した帰着コードの停止・時間・問い合わせ回数と、PRF 実験の分布の実現を導きます。`transform` はこれらを共通論理の証拠付きコード変換に接続します。

現在の実行モデルでは、安全性パラメータの符号化に加え、問い合わせ上限を公開テープの入力として与えます。容量を `c(n)` とすると、容量テープは `min(q(n), c(n))` セルです。したがって入力長は `n+1+q(n)` 以下です。指数的に大きい関数領域の全容量を初期化する必要はありません。容量の切り詰めと型付き実験の一致は `SourceRealization` の前提で確認します。コードをパラメータごとに生成し直す操作はありません。このモデルは、公開上限を受け取るモデルです。安全性パラメータだけから任意の上限関数を計算することや、そのモデルとの同値性を主張していません。

[PRFCounterLogic.lean](../Foundation/Constructions/Symmetric/PRFCounterLogic.lean) は、この帰着を既存の二前提規則に登録します。`bounded_sum` は左右の PRF 上界 `ε₀`・`ε₁` から暗号化の上界 `ε₀+ε₁` を導きます。`sharedDerivation` は同じ PRF 仮定を二回使います。`run` は元の任意の有限コードから、左右二つの帰着コードが生成されることを証明します。`loss` は損失が `2ε` になることを証明します。共通の証拠付き帰着抽出は、生成コードそのものに停止・資源・分布の証拠を付けます。`bounded` は時間 `t′`、問い合わせ回数 `q` の PRF 安全性から、時間 `t`、問い合わせ回数 `q` の暗号化安全性を導きます。`secure` は同じ資源クラスで漸近的な安全性を輸送します。

[CounterWhole の例](../Foundation/Examples/CounterWhole.lean) は、暗号化を一回問い合わせる固定コードについて、任意のパラメータ・左右の選択・関数表での元の停止と出力分布を証明します。このコードの証拠を論理へ渡し、抽出した資源証拠のコードと生成コードが一致することを確認します。元のコードは27遷移、保守的な帰着上界は1809遷移です。左右の生成コードは実際には39遷移で停止し、38遷移では未停止です。さらに、一回目の暗号文を二回目の左平文として使う有限コードについても、任意の関数表で元の停止・出力分布を証明し、論理の証拠付き帰着抽出へ接続しています。この元のコードは55遷移、帰着上界は6765遷移です。全状態と二回分の記録の一致を証明し、実行は81遷移で完了、80遷移では未停止となることを検査します。検査用の関数は意図的に安全でないため、安全性の結論には PRF 安全性の仮定が必要です。


## ワンタイムパッドの有限コードと無条件の安全性

[Machine/OneTimePad.lean](../Foundation/Crypto/Semantics/Machine/OneTimePad.lean) と [OneTimePadNative.lean](../Foundation/Constructions/Symmetric/OneTimePadNative.lean) は、一様な同じ長さの鍵を一回だけ使うワンタイムパッドを実装します。平文と鍵が `L` ビットの場合、暗号化は `k ⊕ m`、復号は `k ⊕ c` です。`⊕` は各ビットの排他的論理和です。計算困難性の仮定は使いません。機械が使う乱数は、既存の公平な一ビットの乱数命令です。

鍵生成コードは6命令、暗号化・復号コードは共通の17命令です。鍵生成には、幅を表す `L` セルの公開入力を与えます。暗号化・復号の入力形式は、鍵と本文のビットを交互に配置した `2L` セルの要求です。これらのコードは幅を変えても同じです。一遷移で行う処理は、一セルの読み書き、ヘッド移動、分岐、乱数ビットの生成など、既存のビット機械の命令です。

| 処理 | 妥当な入力で証明した停止上界 |
| --- | --- |
| `keygenCode` による `L` ビットの鍵生成 | `5L+2` |
| `encryptionCode` による暗号化 | `8L+2` |
| `decryptionCode` による復号 | `8L+2` |
| `freshEncryptionCode` による鍵生成と暗号化 | `8L+2` |

鍵生成と暗号化を一つの17命令のコードで行う `freshEncryptionCode` も用意しています。このコードは平文の各ビットを有限制御に保持してから、その入力セルに鍵の乱数ビットを書き込みます。暗号文は出力テープに書きます。停止時には、内部入力テープに鍵が、出力テープに暗号文が残ります。観測者へ公開するのは出力テープだけです。`fresh_typed_run` は、この実行の最終状態が、一様な鍵と、その鍵で暗号化した平文の同時分布を厳密に実現することを証明します。暗号文だけを直接一様に生成して鍵との関係を省略する実装にはしていません。

`keygen_uniform` は実コードの出力が厳密に一様な鍵になることを証明します。`encryption_correct` と `decryption_correct` は、実コードの出力が方式の暗号化・復号の定義と一致することを証明します。`roundtrip` は、実際の鍵生成・暗号化で残った鍵と暗号文を復号の呼出しに渡した場合、元の平文が必ず返ることを証明します。各呼出しの入力テープは、指定した入力形式で初期化する実行モデルです。呼出し間の要求の符号化と、出力テープをビット列として読む数学的な観測を、一遷移の命令とは扱いません。

`keygenProgram`、`encryptionProgram`、`decryptionProgram`、`freshEncryptionProgram` は、既存の `BoundedProgram` に接続した証拠付き有限コードです。全入力・全乱数分岐について多項式時間で停止します。暗号化・復号の任意の入力列 `N` セルに対する共通上界は `4N+4` 遷移です。入力の末尾が一ビットだけ残る場合、低水準コードはその未完成の組を出力に含めず停止します。暗号方式の正しさを主張する入力は、型付きの同じ長さの鍵と本文から構成した完全な組です。長さの関数 `L(n)` が多項式で抑えられる場合は、`profile_time_polynomial` によって、安全性パラメータに対する鍵生成と暗号化・復号の時間上界も得られます。

`Native.goal` の識別優位は、左右の平文をこの実コードで暗号化し、その出力を確率的な観測者に渡す実験から定義しています。`perfect_secrecy` は左右の出力分布が等しいことを証明します。`advantage_zero` は、全ての長さ・等長の平文対・確率的な観測者について識別優位が厳密にゼロであることを示します。`bounded` は既存の具体的な安全性上界を提供します。`secure` は任意の攻撃者クラスでの漸近的な安全性を導きます。計算量に制約のない観測者まで扱うため、資源を制約したクラスも含まれます。

既存の二前提論理には、鍵をそのまま出力する恒等写像を `Generator` として登録します。これは鍵を伸ばす生成器ではありません。実分布と理想分布がともに一様なので、`generator_advantage_zero` で各前提の識別優位ゼロを証明します。`logic_bounded` はこの証明で前提を満たし、既存の二前提導出から暗号化の上界ゼロを導きます。`ciphertext_eq_registered` は、この型付き方式の暗号文と、実行コードの出力の符号化の一致を保証します。外部から PRG 安全性の仮定を与える必要はありません。共通の証拠付き帰着抽出は、左右二つの生成コードと資源証拠を保持します。

[実行例](../Foundation/Examples/OneTimePadNative.lean) は、空の入力、3ビットの鍵生成、暗号化・復号、生成した鍵の保持、停止直前の打切り、コードの自然数符号化を検査します。3ビットの鍵生成は17遷移、暗号化・復号と鍵生成を含む暗号化は26遷移です。25遷移での暗号化は未停止です。任意の幅に対する復号の正しさと、同じ固定コードの攻撃者を使った論理の安全性定理・証拠付き帰着抽出も検査します。暗号文の最初のビットを読む5命令の観測者についても、3遷移での出力を証明し、実装から定義した安全性実験の識別優位ゼロを確認します。

この安全性定理は一つの鍵を一回だけ使う実験についての定理です。`reused_key_reveals_xor` は、同じ鍵で暗号化した二つの暗号文の排他的論理和が、二つの平文の排他的論理和になることを証明します。実行例の `reused_key_attack` は、一ビットの鍵を再利用して既知のゼロを暗号化した後に、ゼロと一の暗号化を完全に識別できることを示します。

## 意味論に依存しない理論提示への再構成

`Foundation/Logic/Presentation.lean` は暗号のモジュールを参照しない論理の核です。判断の型、規則ごとの有限の前提と結論を指定して導出を作ります。仮定の置換、置換の恒等則と結合則、モデルへの解釈、解釈と置換の整合性を証明しています。モデルは命題に限定せず、数値や証明構造も保持できます。仮定の解釈を指定すると、自由な構文モデルからの解釈が一意に定まります。

暗号の具体例は `Foundation/Crypto/Logic/Presented` に配置します。

| ファイル | 役割 |
|---|---|
| `Syntax.lean` | 安全性を指定せずに、型付きの公開パラメータ、帰着規則、導出、コード生成を定義します。パラメータの変換を構文として保持する選択肢も提供します。 |
| `Interpretation.lean` | パラメータの変換を保存する解釈を与え、安全性のモデルと証明構造を保持するモデルを構成します。仮定の置換との整合性を証明します。 |
| `Reconstruction.lean` | 既存の一般化された導出の証明構造との往復を証明します。全既存導出について、計画と全入力コードに対する出力を保存する構文上の代表が存在します。 |
| `Resources.lean` | 解釈した明示的な証明構造から、優位性の上界と実行証明書を取り出します。再構成は停止・資源・分布を含む証明書全体を保存します。 |
| `Legacy.lean` | 元の単一前提・二前提の公開 API にも、生成コードを保存する再構成を提供します。 |

`PRGLogic.derivation` は新しい核の導出を解釈して構成します。さらに `PRGPresented.proof` は、擬似乱数生成器、時間上界、公開メッセージの族を受け取らない固定した導出です。同じ仮定を二回使用し、構文だけから二つの帰着コードを生成します。それぞれの意味を解釈すると、擬似乱数生成器の優位性上界から暗号の上界 `2ε` を導きます。

この核は有限個の前提を持つ推論規則の自由な論理です。任意の依存型を含む一般化代数理論、無限個の前提、任意の証明等式による商を実装したとは主張しません。また、既存の登録済み規則との対応は、意味論上の全ての真な安全性主張を証明できるという完全性ではありません。チェックポイントでの振り返りは [再構成の記録](logic-reconstruction.md) にまとめています。
