# Issue #8 の実装プラン

この計画では、型付きの多入力推論を表す構文を既存の証明木に接続し、PRG 暗号の二つの帰着コードと安全性上界を再現します。その後、証明変形の経路と、その経路の整合性を段階的に実装します。

- 対象は [Issue #8](https://github.com/CryptoVerification/Foundation/issues/8) です。
- 基準コミットは `0501570b30220275a88f98d0316571ed79f20c97` です。
- 作業ブランチは `issue-8-polygraphic-security` です。
- Lean と mathlib は、現在の `v4.33.0` を使用します。
- この文書は実装計画と進捗を記録します。実装済みの範囲は直下に明記します。後続段階の新規モジュールと宣言名は予定です。

## 現在の実装範囲

段階1の純粋構文、段階2の既存の暗号論理への接続、段階3の PRG の局所的な証明を実装しました。次のモジュールが実装の入口です。

- `Foundation/Logic/Polygraph/Basic.lean` は、恒等・基本規則・順次合成・横合成・仮定の位置の対応を定義します。共通の文脈から複数の出力を作る `tuple` も、有限積の組を作る操作として明示します。
- `Foundation/Logic/Polygraph/Presentation.lean` と `Interpretation.lean` は、証明木との対応と直接の解釈の一致を証明します。`Occurrences.lean` は、葉の出現順と、置換した際の出現の展開を扱います。
- `Foundation/Crypto/Logic/Polygraph/{Syntax,Interpretation,Resources,Translation}.lean` は、純粋なコード生成、安全性、上界、実行の証拠を接続します。一般的な規則体系間の翻訳の構文は後続です。現在の `Translation` は、コードと上界を直接評価するモデルとの対応を証明します。
- `Foundation/Crypto/Logic/Polygraph/Experiment.lean` は、同じ実行インターフェースのまま比較する優位性を変更する最小の補助構成です。任意の確率的実験の構文はまだ実装していません。
- `Foundation/Constructions/Symmetric/PRGPolygraph.lean` は、PRG 置換、一様パッドの分布一致、三角不等式の三種類の規則から証明を構成します。`targetWitnesses_eq` は、得られる二つの実行の証拠を既存の `mapWitness` と比較します。
- `Foundation/Examples/{PolygraphLogic,PRGPolygraphCompatibility,PRGPolygraph,PolygraphAudit}.lean` は、実行例、既存の合成規則との互換性、基本規則による PRG の例、公理依存の検査を分けます。

この段階の構文は括弧を残した合成式です。構造法則による同値類、3セルと4セル、停止性・合流性、合成規則の展開経路は未実装です。一般的なハイブリッド論法への拡張も後続に置き、まず PRG の二段の比較までを対象にします。

健全性と具体的上界の定理は、現在は `Crypto/Logic/Polygraph/Interpretation.lean` にまとめています。計画に記載した `Meta/Polygraph/Soundness.lean` への分割は、後続の定理が増えた際に検討します。

検証では `nix develop path:. -c lake build` が4,099ジョブで成功しました。`nix develop path:. -c lake env lean Foundation/Examples/PolygraphAudit.lean` を直接実行し、再構成、解釈、置換、コード、上界、安全性、PRG の実行の証拠に関する15宣言の公理依存を確認しました。依存は `propext`、`Classical.choice`、`Quot.sound` の範囲であり、`sorryAx` や新規の安全性公理への依存はありませんでした。既存モジュールの未使用の簡約引数などに関する警告は残っています。

## 1. 先に固定する設計

### 1.1 論理的な仮定を複製できる構文を採用します

ポリグラフは、基本操作、その合成、合成された操作間の変形を次元ごとに表す構造です。今回の推論層では、0セルを一つとし、1セルを判断の有限列、2セルを判断列から判断列への推論として扱います。判断とは「ある対象について、指定した条件の下で安全性が成立する」という主張の構文です。

既存の `Foundation.Logic.Presentation` は、型に相当する判断と、多入力・一出力の推論規則を持ちます。`Derivation` は、同じ文脈の仮定を何度でも参照できる証明木です。文脈は、仮定を位置で識別する有限列です。

この性質を保つため、論理層には有限積の構造を採用します。有限積は、複数の結果を組にし、同じ入力を複数の推論で使用できる構造です。多出力の意味は、同じ文脈を使う複数の証明木で与えます。

最初の表現では、仮定の位置の付け替えを一つの構造操作にまとめます。入力文脈を `Γ`、出力文脈を `Δ` とすると、この操作は、`Δ` の各位置が参照する `Γ` の位置と、その判断の一致証明を保持します。同じ入力位置の複数回の指定で複製を表します。入力位置を指定しないことで破棄を表します。順序の変更も、この対応で表します。

この操作が複製するものは論理的な仮定への参照です。鍵、私有状態、乱数、実行結果を複製する規則には解釈しません。コードの解釈でも、複製する対象は証明の解釈やコード変換を表す純粋な値です。確率的な処理を一回実行して結果を複製することと、処理を二回実行することを同一視しません。

### 1.2 合成式と、その式が表すセルを区別します

最初に作る `Diagram` は、括弧を保持する合成式です。入力・出力の文脈を型に持ち、次の構成子を予定します。

| 構成子の役割 | 入力と出力 |
| --- | --- |
| 恒等推論を作ります。 | 同じ文脈の間を結びます。 |
| 登録した基本規則を適用します。 | 規則の前提列から、結論一つの列へ結びます。 |
| 順次合成します。 | 中間の文脈が一致する二つの推論を結びます。 |
| 横合成します。 | 二つの入力列と二つの出力列を、それぞれ連結します。 |
| 仮定の位置を付け替えます。 | 判断を保つ位置の対応に従って、仮定を選択・複製・破棄します。 |
| 共通の文脈から出力の組を作ります。 | 出力の各位置について、一出力の推論を指定します。 |

結合則や単位則によって式を同じとみなす関係は、式そのものとは別に定義します。必要に応じて、その関係による同値類から、構造法則が厳密に成立するセルを構成します。生の合成式だけを自由な2圏の実装とは呼びません。

既存の証明木に解釈できることだけで、自由な構造との同型が得られたとは主張しません。逆方向の構成、合成の保存、同一視する構造法則を証明した範囲を明示します。

### 1.3 証明の意味を保つ変形だけを登録します

推論の変形を3セルとして、合成可能なデータで保持します。Lean の `Prop` は命題とその証明を表す領域です。変形経路を区別する層は `Type` のデータとして定義し、既存の等式証明をその解釈に使います。

同じ前提・結論を持つ任意の二つの安全性証明を結ぶことは要求しません。異なる帰着コードや上界を持つ証明があるためです。最初は、指定した構造変形と合成規則の展開から生成される関係だけを対象にします。

推論を2セル、推論の変形を3セルに置く場合、3セルの経路どうしを比較する生成子は4セルです。3セルを実装した段階と、4セルによって経路の整合性を構成した段階を区別します。

### 1.4 実験の変形は別の層に置きます

暗号実験は、乱数や攻撃者とのやり取りを含む確率的な処理です。実験層では、入出力・問い合わせの型、実験、実験間の変形を扱います。推論層の仮定の複製や横合成から、実験の複製や暗号方式の並列合成を導くことはしません。

次の三つの関係を分けます。

1. 分布が完全に一致する変形です。
2. 失敗事象などから、確率差に数値上界を与える変形です。
3. 攻撃者を変換し、計算量に基づく安全性を輸送する帰着です。

三つ目の帰着は、コード変換、許容される攻撃者の範囲、停止、資源、分布の実現、上界の変換を保持します。誤差の数値だけを持つ辺で代用しません。

## 3. 実装する順序と完了条件

### 段階1：純粋構文と既存の証明木との対応を作ります

予定する追加ファイルは、`Foundation/Logic/Polygraph/{Basic,Presentation,Interpretation}.lean` と `Foundation/Examples/PolygraphLogic.lean` です。

`Basic` は文脈の連結、判断を保つ位置の対応、型付きの `Diagram` を定義します。`Presentation` は既存の規則と証明木への接続を定義します。`Interpretation` は生成子の解釈から合成全体の解釈を構成します。

中間の意味を `Forest Γ Δ` と呼びます。これは、出力文脈 `Δ` の各位置について、入力文脈 `Γ` からの既存の証明木を一つ持つデータです。以下の宣言名を予定します。

- `toForest` は、合成式を証明木の組に解釈します。順次合成は仮定の置換に対応します。
- `ofDerivation` と `ofForest` は、既存の証明木から合成式を構成します。各子の証明が共通の文脈を使えるよう、仮定の位置の対応を明示します。
- `toForest_ofDerivation` と `toForest_ofForest` は、既存の証明木を復元できることを証明します。
- `eval_toForest` は、直接の合成的な解釈と、既存の証明木を経由した評価の一致を証明します。

逆向きの対応は、まず証明木の意味に関する往復を証明します。`ofForest (toForest d) = d` という生の式の等式は要求しません。段階4では限定した構造変形による比較を扱います。任意の式と、証明木を経由して再構成した式を結ぶ完全な構造法則の実装は、別の義務として残します。

各証明の葉について、仮定の位置を出現順に記録する `occurrences` も定義します。仮定を置換すると、その仮定の各出現を置換先の葉の列に展開することを証明します。出現回数を集合に変換して失わないようにします。

**完了条件**：零前提・一前提・二前提・三前提の規則を表現できます。空の出力列、仮定の並べ替え・破棄・二回使用を扱えます。境界の不一致を型で排除できます。直接の解釈が順次合成・横合成と位置の対応を保存することを証明します。

### 段階2：暗号のコード・安全性・実行の証拠を接続します

予定する追加ファイルは、`Foundation/Crypto/Logic/Polygraph/{Syntax,Interpretation,Resources}.lean` と `Foundation/Crypto/Meta/Polygraph/Soundness.lean` です。

既存の `Presented.Parameters` と `FamilyExpr` を使用します。一出力の新構文から `Presented.Derivation` への解釈を `toPresented` と呼びます。既存の導出から構成する逆方向も定義します。

コード生成の `plan` と `run` は、純粋構文だけから定義します。安全性の意味論を引数に取りません。既存の `plan` を `toPresented` の結果に適用する構成を最初の実装とし、その構成が構文の合成に対応することを証明します。

安全性については `sound`、具体的な上界については `bounded` を構成します。実行の証拠は `General.Tree` への指定した解釈から構成します。その証拠が持つコードと `run` の出力の一致を証明します。

資源の種類や単位が異なる機械を、一つの数値に統合しません。証拠の比較に型の変換が必要な場合は、その変換を明示します。証拠全体の等式が証明できる場合と、コード・資源値・分布などの各成分を対応させる場合を区別します。

**完了条件**：同じ新構文からコード、数値上界、安全性、実行の証拠を得られます。置換によるコードと上界の合成を証明します。コードの一致だけから、証明木や資源上界の一致を推論しません。

### 段階3：PRG 暗号を基本規則から構成します

PRG は擬似乱数生成器です。最初の暗号の実証として、PRG の出力と平文の排他的論理和を取る一回限りの暗号を扱います。

予定する追加ファイルは、`Foundation/Constructions/Symmetric/PRGPolygraph.lean` と `Foundation/Examples/PRGPolygraph.lean` です。実験変形の共通化に必要な最小部分は、`Foundation/Crypto/Logic/Polygraph/Experiment.lean` に置きます。

証明は、次の基本要素から構成します。

1. 各平文について、暗号文の識別器から PRG の識別器を構成します。識別器は、二つの実験を見分けようとする攻撃者です。生成コードには既存の左右の帰着コンパイラを使います。
2. 一様乱数に固定の平文を排他的論理和で加えても分布が変わらないことを、完全な分布一致として扱います。
3. 左右の理想実験の分布一致から、共通の中間実験を定めます。
4. 左右の確率差を三角不等式で接続します。

この最小の実験構文では、PRG 置換と分布一致を別の生成子として残します。既存の `advantage_le` や暗号全体の `Binary.encryption` を一つの生成子にした例は、互換性の確認には使えますが、この段階の完了条件には数えません。

`ThreeGames` の具体例は真偽値の問い合わせ型を持ちます。一方、PRG 暗号の観測対象はビット列です。三角不等式の数値補題を再利用することと、認証済み帰着の機械インターフェースを再利用することを分けます。PRG の機械に必要な変換・実現の証明を構成してから接続します。

**完了条件**：新構文の証明は安全性の意味論を引数に取りません。同じ PRG の仮定の出現が二回残ります。生成する二つのコードは、順序と仮定の位置を含めて既存の `PRGPresented.run` と一致します。安全性パラメータ `n` に対して、各帰着先の共通上界 `ε(n)` から `2ε(n)` を導きます。停止・資源・分布の実現を各出力に接続します。

段階1から3までを、最初の安全性導出の実証とします。段階3の証明木は、既存の一規則の証明より細かくなる可能性があります。既存との比較では、コードと数値上界をまず比較し、証明木全体の等式は必要な展開との対応が証明できた範囲に限定します。

### 段階4：限定した構造変形と経路の整合性を作ります

予定する追加ファイルは、`Foundation/Logic/Polygraph/{Translation,Coherence,Normalization}.lean`、`Foundation/Crypto/Meta/Polygraph/Normalization.lean`、`Foundation/Examples/PolygraphCoherence.lean` です。

最初の正規化は、順次合成の恒等を除去し、合成を右結合にする範囲に限定します。横合成や基本規則の内部にも変形を適用できるようにしますが、横合成の分配による証明の複製や、任意の暗号帰着の正規化は含めません。

実装する対象を次の三つに分けます。

- `StructuralStep` は、基本変形一回と、その適用場所を持つデータです。
- `StructuralPath` は、始点・終点を保って基本変形を接続したデータです。推論層の3セルの候補になります。
- `Coherence` は、指定した二つの平行な変形経路を結ぶデータです。推論層の4セルの候補になります。

停止性は、式の大きさと左側に入れ子になった順次合成の重みを使い、各基本変形で減少することを証明する方針です。具体的な重みは構文の確定後に定義します。単位除去と結合の重なり、および結合どうしの重なりを列挙し、それぞれの合流経路を構成します。型の境界を任意にした有限個の規則形式で、対象とする競合を網羅したことも証明します。

合流先の存在の証明と、その経路を結ぶ4セルの構成は別々の成果物にします。対象とする書き換え関係についてのみ、停止性・合流性・経路の整合性を主張します。

規則を別体系の導出へ展開する `Translation` も接続します。展開と置換を行う順序の対応を、合成可能な経路として表します。異なる規則体系の式を直接比較する際は、両方を含む拡張体系、または共通の展開先を明示します。

**完了条件**：正規化経路をデータとして取り出せます。限定した規則の停止性と合流性を証明します。競合に対する4セルを構成します。各構造変形について、コードと評価した上界の保存を証明します。実行の証拠の保存は、指定した証明木との対応を通じて証明します。`CompositeRule` の展開について、既存の保存定理を新しい経路の解釈から再現します。

有限積の全構造法則や、すべての合成規則展開について、この段階で完全な経路の整合性が得られたとは主張しません。

### 段階5：実験変形の構文を一般化します

段階3の最小の実験構文を拡張します。追加候補は、`Foundation/Crypto/Logic/Polygraph/{Experiment,ExperimentInterpretation}.lean` です。

一様乱数の全単射による置換、独立な乱数生成の交換、計算量に基づく置換、失敗事象による評価、隣接する確率差の接続を扱います。全単射や独立性、同時分布の周辺分布、攻撃者がアクセスできる状態を、各生成子の条件として保持します。

カップリングは、二つの実験を周辺分布として持つ同時分布です。既存の `Probability/Coupling` と `Oracle/CoupledRun` を再利用し、生成子の健全性を証明します。失敗事象の確率上界は別の証明として入力します。

厳密な等価変形と、上界を緩める変形は別の関係にします。後者の合成には上界の単調性を使います。逆向きの変形や、上界の等式は自動的に与えません。

**完了条件**：推論層への解釈が合成を保存します。完全な分布一致、統計的な評価、計算量に基づく帰着の保証を混同しません。PRG の例が、一般化後の生成子でも構成できます。

### 段階6：ハイブリッド論法と Encrypt-then-MAC に広げます

ハイブリッド論法は、二つの実験の間に中間実験を置き、隣接する確率差を足して全体を評価する方法です。追加候補は `Foundation/Crypto/Meta/Polygraph/{FiniteHybrid,UniformHybrid}.lean` です。

まず長さを固定した有限列について、空の列、一段の列、複数段の列を扱います。新構文から上界の有限和、出力コードの順序、各出力の実行の証拠を得ます。

安全性パラメータに依存する長さに広げる際は、すべての使用位置に共通する上界、多項式回数、一つの固定コードによる実行の証拠を要求します。固定した位置ごとの無視できる上界だけでは代用しません。`UniformHybrid.executed_*` の接続は、その固定機械が実現する実験の範囲で行います。任意の可変長証明のコード生成が完成したとは扱いません。

Encrypt-then-MAC は、暗号化した結果にメッセージ認証符号を付ける方式です。追加候補は `Foundation/Constructions/Symmetric/EncryptThenMAC/Polygraph.lean` です。高水準の二前提規則と、秘匿性・完全性・結合の三段階への展開を接続します。

**完了条件**：有限列では隣接する上界の和を再現します。可変長では既存の共通上界と固定コードの条件を保持します。Encrypt-then-MAC では、二つの前提、上界の和、生成コード、指定した実行の証拠を保存します。

## 4. 変更をレビューする単位

6. 段階5の実験変形の一般化を追加します。
7. 段階6の固定有限長のハイブリッド論法と Encrypt-then-MAC を、それぞれ追加します。

各実装の変更で、対応するモジュールを `Foundation.lean` に追加します。保証が増えた時点で `docs/crypto-logic.md` と本文書の進捗を更新します。未実装の保証を文書に完了済みとして書きません。

## 5. 検証する内容

### 5.1 数学的な契約を検証します

- 意味論を与えずに、純粋構文から実行可能な計画を作れることを、`#eval` を含む例で確認します。
- 一つの仮定の二回使用で、出力と上界の二つの寄与が残ることを確認します。
- 境界が違う合成や、判断が違う位置の対応が受理されないことを、失敗を期待する例で確認します。
- 同じ境界を持つ異なる基本規則を、コードなどで区別するモデルを用意します。すべての平行な導出を同一視する設計になっていないことを確認します。
- 二通りの構造変形が重なる例で、合流経路と、その比較データを構成します。
- 上界の緩和を扱う場合は、等式保存と不等式による輸送を別々に検証します。
- 閉じた安全性証明が生じる場合は、その根拠が分布一致などの証明済みの事実にあることを確認します。零前提規則を一律に禁止するのではなく、無根拠な計算量に基づく安全性を追加しないことを検査します。

### 5.2 ビルドと公理依存を検査します

実装中は、変更したモジュールに対応する対象をビルドします。全体の受入時には、リポジトリの開発環境で次を実行します。

```sh
nix develop path:. -c lake build
```

`Foundation/Examples/PolygraphAudit.lean` を追加し、公開する健全性、具体的上界、PRG のコード一致、停止性、合流性、経路の整合性の定理について `#print axioms` を実行します。`sorryAx` と新たな安全性公理の依存がないことを確認します。Lean の既存の論理公理への依存は別途記録します。

公理依存の表示は `lake env lean` で直接実行して確認し、キャッシュ済みのビルドが成功したことだけで代用しません。意味のある出力例と、コードに対応する停止・資源・分布の実現の定理も確認します。

本文書だけの変更では、差分とリンク先の存在を確認します。Lean の実装を変更していない段階では、ビルド成功や公理検査の完了は報告しません。
